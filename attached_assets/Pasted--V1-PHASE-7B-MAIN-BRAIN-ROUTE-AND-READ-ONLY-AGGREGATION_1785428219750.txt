=========================================================
READ-ONLY CONTRACT
=========================================================

Calling the Main Brain route must not:

- generate a thesis
- resolve a thesis
- update a thesis timestamp
- calculate a new verdict
- rescore a strategy
- select a new strategy
- update learning weights
- insert Journal records
- update Journal records
- create an active trade
- close an active trade
- update active-trade management
- invoke execute_trade_gateway
- send a broker request
- send Discord messages
- mutate Databento caches
- mutate canonical interface dictionaries
- update “last viewed” timestamps
- write to the database
- change AUTO_FIRED_KEYS
- change any trading mode

Prove this with before/after runtime assertions.

=========================================================
SAFE COPY AND SERIALIZATION
=========================================================

The route must return serialization-safe copies.

Requirements:

- no raw mutable canonical dictionaries returned by reference
- no database connection objects
- no locks
- no sets
- no enums without serialization handling
- no NaN or Infinity
- no unhandled datetime objects
- no callable objects
- no internal exception objects
- no secrets
- no broker credentials
- no webhook URLs

Test that caller mutation of a returned payload does not mutate canonical state.

Repeated calls with unchanged source data must remain semantically stable.

=========================================================
AVAILABILITY AND FAULT ISOLATION
=========================================================

The endpoint must remain available if an optional subsystem fails.

At minimum isolate:

- Left Brain
- market intelligence
- thesis
- verdict
- strategy scanner
- active trades
- Manager
- gateway summary
- Journal
- Coach
- database-derived performance
- alerts
- decision timeline
- broker-health summary

A failure in one section must:

- not cause the full route to return HTTP 500
- produce the documented fallback value
- mark that section unavailable
- append a stable error code
- avoid exposing exception text or secrets
- leave healthy sections intact

Use deterministic error identifiers such as:

- coach_unavailable
- journal_unavailable
- scanner_unavailable
- active_trade_unavailable
- timeline_partial
- broker_status_unavailable

Use the exact codes approved in the brief where specified.
