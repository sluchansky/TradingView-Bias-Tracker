Do not begin another phase and do not add any new indicators, strategies, dashboard modules, scoring rules, AI features, or entry logic.

Prepare the current completed Phase 1–3 build for deployment and controlled testing.

TASKS

1. FINAL CODE REVIEW

Review all Phase 1–3 changes for:

- Broken imports
- Missing environment variables
- Development-only paths
- Hardcoded localhost URLs
- Incompatible database schemas
- Duplicate event listeners
- Duplicate Discord alerts
- Duplicate trade submissions
- Unhandled API errors
- Restart recovery problems
- Race conditions between alerts
- Mobile dashboard rendering errors

Do not refactor unrelated working code.

2. RUN ALL TESTS

Run:

- Phase 1 thesis hysteresis tests
- Phase 2 dashboard and persistence tests
- Phase 3 thesis enforcement tests
- Existing golden smoke tests
- Existing webhook tests
- Existing TradersPost tests
- Existing journal tests
- Frontend build
- Backend startup test
- Dashboard JavaScript validation

Report every passing and failing test.

Do not claim deployment readiness if any money-path test fails.

3. DEPLOY IN SHADOW MODE

Deploy with thesis enforcement remaining in SHADOW MODE.

Required behavior:

- Existing READY verdict behavior remains unchanged.
- Thesis gate evaluates every READY setup.
- Shadow gate records WOULD_ALLOW or WOULD_BLOCK.
- Shadow gate never changes a live verdict.
- Shadow gate never changes an order.
- Shadow gate never changes entry, stop, target, contracts, or risk.
- Existing TradersPost behavior remains unchanged.
- No automatically restored thesis may submit a trade after restart.

4. CONFIRM ENVIRONMENT SETTINGS

Verify the production environment has the correct values for:

THESIS_DASHBOARD_ENABLED=1
THESIS_DISCORD_ALERTS_ENABLED=1
THESIS_DB_PERSISTENCE_ENABLED=1
THESIS_ENFORCEMENT_MODE=shadow

Also verify all existing:

- Database variables
- Discord variables
- TradingView webhook secrets
- TradersPost webhook variables
- Dashboard API URLs
- Production domain configuration

Do not expose secrets in the report.

- No duplicate Discord messages are created.
- No test order is sent to TradersPost.

Use a clearly marked non-trading test payload for health checks.

7. LIVE TESTING MODE

For the initial test period:

- Keep thesis enforcement in shadow mode.
- Keep auto-trading in its current state; do not enable it automatically.
- Do not increase contract size.
- Do not change risk settings.
- Do not loosen READY thresholds.
- Do not change confidence thresholds.
- Do not modify the scoring model during the collection period.

Collect every valid setup whether the shadow gate agrees or conflicts.

9. TESTING SAMPLE

Do not make enforcement decisions from only a few trades.

Initial checkpoint:

- Minimum 25 completed, triggered setups

Useful checkpoint:

- Minimum 50 completed, triggered setups

Stronger checkpoint:

- 100 completed, triggered setups across normal market conditions

Show results separately by:

- Instrument
- SCALP versus SWING
- Long versus short
- Trading session
- ALIGNED
- PARTIALLY_ALIGNED
- NEUTRAL
- CONFLICTING
- INVALIDATED
- NO_THESIS

Do not combine every instrument and mode into one misleading statistic.
