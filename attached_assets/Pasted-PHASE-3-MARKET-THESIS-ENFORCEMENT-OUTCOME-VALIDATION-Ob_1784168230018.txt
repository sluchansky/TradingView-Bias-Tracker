PHASE 3 — MARKET THESIS ENFORCEMENT + OUTCOME VALIDATION

Objective:
Make the Market Thesis Hysteresis Engine actively evaluate every trade setup, while initially operating in SHADOW MODE so existing live behavior is not changed until results are verified.

Do not add another major dashboard or unrelated strategy.
Do not redesign the existing thesis engine.
Build on Phase 1 and Phase 2.

==================================================
1. ADD THESIS ENFORCEMENT MODES
==================================================

Add a configurable environment setting:

THESIS_ENFORCEMENT_MODE=shadow

Supported values:

off
- Thesis engine is recorded and displayed only.
- It has no effect on setups.

shadow
- Thesis engine evaluates every setup.
- It records what it would have allowed, blocked, downgraded, or upgraded.
- It must not change the actual existing verdict or prevent an order.

enforced
- Thesis alignment becomes part of the actual READY decision.
- Conflicting or invalidated thesis states can block a setup.

Default must be:

THESIS_ENFORCEMENT_MODE=shadow

Show the current mode clearly on the Thesis Dashboard.

==================================================
2. EVALUATE EVERY TRADE SETUP AGAINST THE THESIS
==================================================

Before any setup becomes READY, evaluate it against the current thesis for that exact instrument.

Create a thesis alignment result with these possible values:

ALIGNED
PARTIALLY_ALIGNED
NEUTRAL
CONFLICTING
INVALIDATED
NO_THESIS

Suggested decision rules:

ALIGNED:
- Trade direction matches thesis direction.
- Thesis state is READY or ACTIVE.
- Thesis confidence meets the required threshold.
- Setup receives a positive thesis confirmation.

PARTIALLY_ALIGNED:
- Direction matches.
- Thesis is still FORMING or confidence is below the strong threshold.
- Setup may continue, but thesis does not provide full confirmation.

NEUTRAL:
- Thesis does not have a confirmed direction.
- Existing setup logic continues unchanged in shadow mode.
- In enforced mode, do not allow thesis confirmation credit.

CONFLICTING:
- Setup direction is opposite the thesis direction.
- In shadow mode, record “WOULD BLOCK.”
- In enforced mode, block the setup from becoming READY.

INVALIDATED:
- Thesis was invalidated or entered cooldown.
- In shadow mode, record “WOULD BLOCK.”
- In enforced mode, prevent the setup from becoming READY.

NO_THESIS:
- No usable thesis exists for the instrument.
- Fail open in shadow mode.
- In enforced mode, behavior should be configurable and default to fail open.

5. PREVENT STALE SETUPS
==================================================

When a meaningful thesis transition occurs:

READY → INVALIDATED
ACTIVE → INVALIDATED
LONG → SHORT
SHORT → LONG

Find open internal setups for the same instrument.

Mark untriggered setups as:

STALE_THESIS

Record:

previous_thesis_id
new_thesis_id
transition_type
stale_reason
timestamp

During shadow mode:
- Only mark and report what would happen.
- Do not cancel live broker orders.
- Do not change existing live execution behavior.

During enforced mode:
- Prevent stale, untriggered internal setups from becoming READY.
- Do not automatically cancel a live broker order unless a separate explicit safety setting is enabled in the future.

8. DEFINE FALSE BLOCKS AND LOSSES AVOIDED
==================================================

Loss avoided:
- Shadow thesis action was BLOCK.
- Original setup would have triggered.
- Original setup hit its stop before its target.

False block:
- Shadow thesis action was BLOCK.
- Original setup would have triggered.
- Original setup reached its target before its stop.

Record both clearly so the thesis engine cannot appear successful simply because it blocked more trades.
