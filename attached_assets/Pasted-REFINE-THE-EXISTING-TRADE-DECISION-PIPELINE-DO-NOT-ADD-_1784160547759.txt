==================================================
1. CREATE A PERSISTENT MARKET THESIS
==================================================

The bot currently appears to recalculate WAIT or READY from individual incoming signals.

Change this so each instrument maintains one persistent active thesis.

Create an ActiveThesis object per instrument:

{
  thesisId,
  instrument,
  direction,
  status,
  createdAt,
  lastUpdatedAt,
  lastStrengthenedAt,
  lastWeakenedAt,
  confidence,
  previousConfidence,
  structureDirection,
  activeZoneId,
  zoneType,
  zoneStatus,
  vwapAligned,
  cvdAligned,
  sweepConfirmed,
  volumeConfirmed,
  sessionPrime,
  entry,
  stop,
  targets,
  invalidationPrice,
  invalidationReason,
  evidenceFor,
  evidenceAgainst,
  expirationAt
}

Supported thesis statuses:

- NEUTRAL
- FORMING_LONG
- FORMING_SHORT
- READY_LONG
- READY_SHORT
- ACTIVE_LONG
- ACTIVE_SHORT
- INVALIDATED
- COOLDOWN

The thesis must not be recreated every time a new alert arrives.

Incoming alerts should update the existing thesis.

==================================================
2. STRUCTURE REMAINS THE FOUNDATION
==================================================

Preserve the existing rule that BOS or CHOCH creates the directional foundation.

Rules:

- Bullish structure may create or strengthen a long thesis.
- Bearish structure may create or strengthen a short thesis.
- An opposite structure signal should weaken the thesis first.
- It should only invalidate immediately when it breaches the saved structural invalidation rule.
- One isolated opposite alert must not instantly reverse the bot.

Do not permit a direct transition from READY_LONG to READY_SHORT or READY_SHORT to READY_LONG without invalidating or expiring the original thesis first.

==================================================
3. KEEP THE EXISTING THREE REQUIRED GATES
==================================================

READY still requires:

- valid structure
- active fresh zone
- correct VWAP side

These remain mandatory gates.

Edge score alone must never override a missing required gate.

If any required gate is missing:

status = FORMING_LONG or FORMING_SHORT

Do not promote the setup to READY.

==================================================
4. PRESERVE CVD AS A HARD FILTER
==================================================

Keep the current CVD behavior:

- Long setup requires bullish or non-opposing CVD.
- Short setup requires bearish or non-opposing CVD.
- Strong opposing CVD vetoes READY.
- Temporary missing or stale CVD should show UNKNOWN rather than immediately creating the opposite thesis.

Record CVD state as:

- ALIGNED
- OPPOSING
- NEUTRAL
- STALE
- UNKNOWN

Display the exact CVD state in the reasoning.

==================================================
5. CONVERT EDGE SCORE INTO PERSISTENT CONFIDENCE
==================================================

Keep the current scoring inputs, but store the result as persistent thesis confidence.

Existing evidence includes:

- BOS / CHOCH
- VWAP alignment
- liquidity sweep
- volume / RVOL
- CVD agreement
- prime session window
- valid zone

Do not reset confidence to zero every time one alert changes.

Confidence should rise or fall as evidence is added or removed.

Use a range of 0–100 for the displayed confidence.

Suggested default interpretation:

0–39:
Weak or invalid setup

40–59:
Setup forming

60–74:
Valid but not ready

75–84:
Ready candidate

85–100:
Strong ready setup

The existing READY threshold may remain configurable, but all mandatory gates must still be present.

==================================================
6. ADD HYSTERESIS TO STOP FLIP-FLOPPING
==================================================

Use separate thresholds for becoming ready, remaining ready, and reversing.

Defaults:

READY_THRESHOLD=75
HOLD_READY_THRESHOLD=60
REVERSAL_THRESHOLD=85
MIN_THESIS_AGE_MS=5000
REVERSAL_COOLDOWN_MS=20000

Rules:

- Promote to READY when confidence reaches the READY threshold and all gates pass.
- Maintain READY while confidence stays above the hold threshold and hard invalidation has not occurred.
- Do not reverse direction unless the opposite setup reaches the reversal threshold.
- Hard structural invalidation may override these thresholds immediately.
- A brief VWAP touch, one candle, or one alert must not reverse the thesis.

==================================================
9. IMPROVE FAST ENTRY WITHOUT CHANGING ITS PURPOSE
==================================================

Fast Entry must remain a timing layer only.

It must not:

- create the higher-timeframe thesis
- reverse the thesis
- override missing structure
- override a consumed zone
- override opposing CVD
- submit a trade when the main setup is not READY

Fast Entry may only sharpen entry timing when:

- thesis status is READY_LONG or READY_SHORT
- all mandatory gates are valid
- direction agrees with the higher-timeframe thesis

Keep the existing 5-second events such as:

- SWEEP_RECLAIM_LONG
- SWEEP_RECLAIM_SHORT
- DELTA_FLIP_BULLISH
- DELTA_FLIP_BEARISH

Require the events to occur within a configurable confirmation window.

Suggested default:

FAST_ENTRY_CONFIRMATION_WINDOW_MS=15000

==================================================
10. PREVENT DUPLICATE READY EVENTS
==================================================

Do not post a new Discord trade card every time the score updates while the same thesis remains READY.

Create a READY event only when:

- the thesis first transitions into READY
- entry, stop, target, or invalidation materially changes
- the thesis is invalidated and later becomes a new setup with a new thesisId

Use thesisId as the deduplication key.
