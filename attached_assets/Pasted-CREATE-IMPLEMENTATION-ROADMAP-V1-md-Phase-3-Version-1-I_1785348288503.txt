SECTION 3 — IMPLEMENTATION PRINCIPLES

Define the rules all future implementation work must follow.

Include these mandatory principles:

1. Databento remains the primary market-data source.
2. Existing Databento ingestion behavior must not be rewritten unless a documented defect requires it.
3. Pine or TradingView compatibility must not interfere with Databento.
4. Existing production behavior must be preserved unless a task explicitly authorizes a behavior change.
5. The Expert owns the verdict.
6. The Partner explains the verdict but never recomputes it.
7. The Manager owns risk preparation and execution coordination but does not create the analytical thesis.
8. The Execution Gateway owns the final order boundary, duplicate protection, and broker delivery.
9. The Journal owns the permanent trade record.
10. The Coach uses completed historical data and never changes the live gate during an active decision or trade.
11. Operator Mode must not expose raw engineering diagnostics.
12. Engineering View must not alter trading state.
13. Every live decision must be traceable through the decision timeline.
14. No subsystem may silently default an unknown instrument to MGC or another market.
15. Every new interface must be versioned.
16. Every behavior-changing task requires regression proof.
17. Shadow-mode validation must precede any material live decision-logic change.
18. No roadmap task may combine unrelated architectural changes into one implementation step.
