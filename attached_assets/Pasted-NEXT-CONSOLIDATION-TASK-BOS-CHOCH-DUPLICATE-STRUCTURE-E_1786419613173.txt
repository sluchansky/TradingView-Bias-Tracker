NEXT CONSOLIDATION TASK — BOS / CHOCH DUPLICATE STRUCTURE EVENTS

Objective:

Eliminate duplicate BOS/CHOCH influence when the same structural event is observed by both TradingView and Databento.

Do NOT remove TradingView structure alerts entirely yet.

Do NOT change structure thresholds, scoring weights, READY/EARLY/WAIT logic, execution, risk, or broker behavior.

We are only eliminating duplicate representations of the same logical event.

2. ADD TRUE SOURCE TAGGING

Every TradingView structure event must explicitly carry:

source = "tradingview"

Every Databento-derived structure event must explicitly carry:

source = "databento"

Do not infer source later from missing fields if it can be recorded at ingestion.

Preserve existing metadata.

3. CREATE A STRUCTURE EVENT IDENTITY

Define a deterministic logical identity for structure events.

Use appropriate fields such as:

instrument
normalized event type
direction
timeframe
structural level / break level
bar timestamp

Do not rely on raw alert text alone.

Suggested logical key:

instrument
+ normalized_structure_type
+ direction
+ timeframe
+ rounded_structural_level
+ event_bar_timestamp

Use instrument tick size when normalizing price.

4. DEDUP WINDOW

When TradingView and Databento both report what appears to be the same logical structure event, only one canonical event may influence downstream structure consumers.

Do not simply deduplicate all BOS events occurring near each other.

Require enough agreement to avoid deleting genuinely separate breaks.

Use:

same instrument
same normalized structure type
same direction
compatible timeframe
price/level within defined tick tolerance
time within a defined bar/time window

Document the exact tolerance.

Do not invent a large arbitrary window.

Prefer the smallest safe window based on current bar cadence.

5. DATABENTO IS CANONICAL WHEN MATCHED

When a TradingView structure event matches a fresh Databento structure event:

Databento event = canonical
TradingView event = shadow/duplicate

Keep the TV event available for audit if useful, but mark:

duplicate_of = <canonical event id>
canonical = false
source = tradingview

The Databento event should show:

canonical = true
source = databento

6. FAIL-OPEN FALLBACK

If there is no matching fresh Databento structure event, TradingView may remain usable as legacy fallback.

Do not cause structure to disappear because Databento is stale/unavailable.

Required behavior:

fresh matching Databento event:
    Databento canonical
    TV shadow

no Databento match:
    existing TradingView behavior allowed

This keeps the migration safe.

7. _recent_smc_signals()

Update the downstream reader so duplicate/shadow structure events cannot be counted twice.

It should consume only:

canonical events
or valid unmatched legacy fallback events

It must ignore records explicitly marked duplicate/shadow for scoring influence.

Do NOT otherwise change the scoring calculation.

8. EVENT HISTORY

If both sources observed the event, diagnostics should still be able to show:

TradingView observed BOS
MATCHED / DUPLICATE

We want to remove duplicate influence, not erase evidence.
