SCALP Measurement Repair — Instrumentation Only

Objective

Repair the SCALP analytics/ghost measurement system so we can determine why SCALP produces WAIT and whether rejected opportunities would have been profitable.

This is a measurement-only change.

DO NOT modify any trading rule, threshold, score weight, risk rule, position sizing, stop/target logic, execution logic, or SCALP eligibility rule.

Before editing, inspect the existing implementation and reuse existing functions/data wherever possible. Keep this small and cost-effective.

⸻

1. Record Failed Gates in Source Analytics

Locate:

* evaluate_strict_setup()
* _gate_debug()
* _record_source_analytics()
* _SOURCE_ANALYTICS_RECORDS

The strict evaluation already computes directional failed conditions.

Add these fields to each source-analytics evaluation:

failed_gates_long
failed_gates_short

Populate them from the existing gate-debug / failed-condition information.

Do not recompute the trading decision separately.

Use the exact same failure information used by the live SCALP decision path so analytics cannot drift from execution logic.

Also record, if readily available without changing decision logic:

edge_score_long
edge_score_short
ready_long
ready_short

Do not create duplicate scoring logic merely to obtain these fields.

⸻

2. Fix the Misleading “500 Setups” Metric

The current analytics ring buffer records repeated full_analysis() evaluations, including dashboard polling.

Therefore:

Setups analyzed: 500

is incorrect.

Change it to:

Evaluations recorded: 500

Then add:

Unique opportunities: N

Use the closest existing canonical setup identity already used by the system.

Prefer the existing _auto_setup_key() semantics if they can safely be reused for analytics.

At minimum distinguish:

instrument
direction
setup/zone identity

Do not change broker/order deduplication.

This is analytics-only deduplication.

⸻

3. Repair Evidence Co-occurrence

Current co-occurrence is invalid because all evidence components are emitted into every analytics record.

For every evidence component emitted by _compute_score_source_attribution(), add an analytics field equivalent to:

scored: bool

scored=True must mean the evidence was actually active/confirmed and contributed positive evidence to that evaluation.

Do not define scored merely as “component exists.”

Then change pairwise co-occurrence analytics so a pair counts only when both components have scored=True in the same evaluation.

Example:

CVD + Volume

should count only when both CVD and Volume actually contributed evidence.

The resulting percentage must no longer be 100% simply because every component is present in every analytics record.

Do not change Edge Score itself.

⸻
