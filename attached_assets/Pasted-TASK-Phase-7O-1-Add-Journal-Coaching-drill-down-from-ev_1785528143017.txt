TASK: Phase 7O.1 — Add Journal Coaching drill-down from every insight to the exact supporting trades.

CONTEXT

Phase 7O delivered the Journal Coaching tab with:

- review coverage
- costliest mistakes
- best behaviors
- followed-plan analytics
- emotion analytics
- rating analytics
- strategy coaching
- session analytics
- discipline trend
- coaching summary
- priority list

The next goal is to make every coaching conclusion clickable and traceable to its underlying reviewed trades.

PRIMARY GOAL

When the operator clicks a coaching insight, open the Journal Trade Log filtered to the exact reviewed trades that produced that metric.

Examples:

- Click CHASED ENTRY
  → show all reviewed trades tagged CHASED ENTRY

- Click FOMO
  → show reviewed trades tagged FOMO

- Click FOLLOWED PLAN: NO
  → show reviewed trades with followed_plan = NO

- Click VWAP CONTINUATION
  → show reviewed trades for that strategy

- Click NEW YORK OPEN
  → show reviewed trades in that session

STRICT SCOPE

This is filtering, navigation, and evidence display only.

DO NOT modify:

- coaching calculations
- analytics formulas
- confidence thresholds
- journal trade data
- review records
- Databento
- scoring
- readiness
- risk
- alerts
- TradersPost
- execution
- learning formulas
- learning thresholds
- Main Brain polling

PART 2 — BACKEND FILTER SUPPORT

Extend the existing journal trades endpoint so it can filter deterministically by:

- mistake tag
- positive tag
- emotion tag
- followed-plan state
- strategy
- session
- instrument
- mode
- source
- review status
- rating field and value
- date range
- result

Requirements:

- filters must combine with AND semantics
- all filtering must occur server-side
- parameterize every query
- no string-concatenated SQL
- excluded trades omitted when the originating metric excludes them
- open trades omitted when the originating metric is closed-trades only
- counts must match the coaching metric exactly

PART 4 — OPENING BEHAVIOR

Preferred behavior:

1. Preserve the current Journal date and account filters.
2. Switch to TRADE LOG.
3. Apply the drill-down filters.
4. Show an evidence banner at the top.

Example:

EVIDENCE VIEW

12 reviewed trades
Clear filter

Do not navigate away from Main Brain.

PART 5 — URL AND HISTORY

Persist drill-down state in the URL or existing router state so:

- refresh preserves the filtered evidence view
- browser Back returns to Coaching
- browser Forward returns to the filtered Trade Log
- sharing the internal route preserves the filter state where supported

Do not create a new global routing system.

PART 6 — COUNT PARITY

For every coaching metric, verify:

coaching card count
=
filtered trade-log count

Examples:

CHASED ENTRY card says 12
→ filtered log returns 12

FOMO card says 9
→ filtered log returns 9

FOLLOWED PLAN: NO says 7
→ filtered log returns 7

If counts differ, treat it as a defect.
