OBJECTIVE

INTRADAY_TREND already exists as a separate selectable trading mode.

Now make it a genuinely independent intraday trading system.

Higher-timeframe bias → intraday structure → location → pullback → confirmation → entry → intraday management → mandatory session exit

Do not redesign unrelated infrastructure.

4. TREND CLASSIFICATION

Build a native Intraday Trend classifier.

Return at minimum:

BULLISH
BEARISH
NEUTRAL
TRANSITION

Evaluate:

* swing highs/lows
* HH/HL or LH/LL structure
* BOS
* CHOCH
* VWAP relationship
* moving-average slope/alignment if already available
* momentum
* ATR/volatility regime
* distance from major levels

Store diagnostic reasons explaining the classification.

Example:

6. 1H CONTEXT

1H is context, not an automatic hard gate.

Classify:

ALIGNED
NEUTRAL
OPPOSED

ALIGNED

15m bullish + unclear 1H:

NEUTRAL

15m bullish directly into strong bearish 1H structure:

OPPOSED

Initially:

* OPPOSED = block unless explicitly enabled by future configuration

Do not reuse the SWING HTF gate.

7. LOCATION REQUIREMENT

Do NOT allow the system to chase price simply because a trend exists.

A valid Intraday Trend setup should occur around meaningful location such as:

* VWAP
* prior breakout/retest area
* 5m support/resistance
* supply/demand zone
* FVG if already implemented reliably
* order block if already implemented reliably
* prior session high/low
* overnight high/low
* opening range boundaries
* significant liquidity level

Record the location used.

Example:

setup_location = VWAP_RETEST

⸻

8. PULLBACK REQUIREMENT

Intraday Trend should primarily enter pullbacks within established trends, not extended impulse candles.

For bullish trend:

look for a controlled pullback toward valid location.

For bearish trend:

look for a controlled rally toward valid location.

Reject setups where price is excessively extended from:

* VWAP
* recent structure
* expected entry location

Use ATR-normalized measurements where practical.

Create a diagnostic:

extension_state = NORMAL / EXTENDED / EXTREME

EXTREME must block entry.

⸻

9. ENTRY CONFIRMATION

After a valid trend + pullback + location, require confirmation.

Valid confirmation may include combinations of:

* liquidity sweep
* rejection candle
* engulfing/reclaim
* micro BOS
* micro CHOCH back toward primary trend
* VWAP reclaim/rejection
* momentum recovery
* delta/CVD confirmation when reliable data exists

Do NOT require every confirmation simultaneously.

Implement a configurable confirmation threshold.

Example:

minimum_confirmations = 2

The exact implementation should use the existing configuration system.

11. STOP LOSS

Stops must be based on trade invalidation.

Preferred hierarchy:

1. beyond pullback swing
2. beyond structure invalidation
3. ATR buffer where appropriate

Do NOT use arbitrary fixed-dollar stops.

Calculate stop distance first.

Then send that distance into the existing canonical risk engine for position sizing.

Never duplicate risk-sizing logic inside Intraday Trend.

⸻

12. PROFIT TARGETS

Initial default management:

TP1 = 1R

Take partial profit when contract count allows.

TP2 = 2R

Allow the remaining position to seek the larger continuation.

For a one-contract position, use the existing one-contract management policy or approximately:

1.5R

Do not introduce a second conflicting order-management engine.

⸻

13. BREAK-EVEN LOGIC

Do NOT immediately move the stop to break-even simply because price briefly touches TP1.

We previously observed trades reaching TP1 and then getting stopped at BE too frequently.

Make break-even movement conditional.

Possible confirmation:

* TP1 achieved AND
* continuation structure remains valid AND
* price establishes beyond the relevant structure

Prefer structural stop advancement where possible.

Record why the stop was moved.

⸻

14. TRAILING

After sufficient favorable movement, allow the runner to trail using structure.

For LONG:

trail beneath confirmed higher lows.

For SHORT:

trail above confirmed lower highs.

Do not trail every candle.
