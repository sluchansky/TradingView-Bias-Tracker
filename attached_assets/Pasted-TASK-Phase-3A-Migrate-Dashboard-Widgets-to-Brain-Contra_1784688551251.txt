TASK: Phase 3A — Migrate Dashboard Widgets to Brain Contract

OBJECTIVE

Make the existing dashboard consume the canonical data.brain contract for all
operator-facing decision information.

This phase is a data-binding migration only.

Do not redesign, remove, combine, move, or restyle dashboard panels yet.

Do not change backend scoring, thresholds, gates, execution, sizing, alerts,
database behavior, or strategy logic.

SOURCE-OF-TRUTH RULE

For migrated operator-facing fields, dashboard JavaScript must read from:

data.brain

Do not independently calculate or reinterpret:

- verdict
- readiness
- direction
- edge score
- edge grade
- reasons
- risks
- next action
- trade plan
- freshness

SCOPE

Apply this migration to the existing Home/dashboard operator-facing widgets.

Do not migrate developer-only diagnostics that are not represented in the Brain
Contract.

Do not modify Cockpit yet unless Home and Cockpit share the exact same rendering
function and separating them would create duplicate logic. Report any such case
before broadening scope.

BACKWARD-COMPATIBILITY FALLBACK

During Phase 3A, a temporary fallback to existing top-level fields is allowed
only when data.brain is entirely absent.

Example:

const brain = data.brain || buildLegacyFallback(data);

Do not use individual mixed fallbacks such as:

brain.score.value || data.edge_score

because valid values such as 0, false, null, or empty lists must not fall through.

When data.brain exists, all migrated widgets must use it exclusively.

Add a clear console warning when the whole-contract legacy fallback is used.

NO CLIENT-SIDE REINTERPRETATION

Dashboard JavaScript must not:

- derive a different verdict
- convert WAIT into READY
- choose direction from another field
- recalculate scores
- merge additional reasons
- manufacture risks
- display a trade plan when brain.trade_plan is null

DASHBOARD SAFETY

Handle safely:

- score value 0
- governor confidence 0
- direction null
- trade_plan null
- empty reasons
- empty risks
- stale price
- missing optional diagnostics

Do not treat 0 or false as missing.
