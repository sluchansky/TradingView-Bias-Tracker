TASK: Avatar Intelligence Layer v3 — Persistent Market Awareness

OBJECTIVE

The avatar should no longer feel event-driven.

It should feel like an experienced trader continuously watching the market, building opinions over time, remembering what it observed a few minutes ago, and naturally discussing the evolving market.

DO NOT modify:

- Trading logic
- Edge score
- Gate calculations
- Position sizing
- Execution
- TradersPost
- Database
- APIs
- Backend services

This is strictly an intelligence, memory, and presentation layer.

----------------------------------------------------
1. SESSION MEMORY
----------------------------------------------------

Create a lightweight in-memory session context.

The avatar should remember:

• Previous confidence
• Previous market bias
• Previous market state
• Previous reasoning
• Previous important observations
• Previous announcements

Memory resets when the page reloads.

No persistence required.

----------------------------------------------------
2. BUILD OPINIONS OVER TIME
----------------------------------------------------

The avatar should evolve its opinion instead of jumping directly to READY.

Example progression:

"I'm beginning to watch this setup."

↓

"Buyers are becoming more active."

↓

"Structure is improving."

↓

"I only need confirmation above VWAP."

↓

"Now this qualifies."

The avatar should feel like it is watching the setup develop.

----------------------------------------------------
3. REFERENCE EARLIER OBSERVATIONS
----------------------------------------------------

The avatar should naturally reference previous observations.

Examples:

"Volume improved compared to a few minutes ago."

"This is the confirmation I was waiting for."

"Earlier I was concerned about structure. That concern is gone."

"Confidence has improved since the session opened."

Never invent information.

Only compare existing values already available.

----------------------------------------------------
4. EXPLAIN CHANGES
----------------------------------------------------

Whenever confidence changes significantly, explain WHY.

Examples:

"My confidence increased because buyers reclaimed VWAP."

"Confidence dropped after structure weakened."

"We lost momentum."

"Liquidity sweep failed."

Never say confidence changed without giving the reason.

Reuse existing diagnostics.

----------------------------------------------------
5. MARKET STORY
----------------------------------------------------

Instead of isolated announcements, create a continuous narrative.

Examples:

"The market opened cautiously."

"Buyers attempted a reclaim."

"Sellers defended."

"Momentum shifted."

"Now buyers appear to be taking control."

Announcements should feel connected.

----------------------------------------------------
6. CONVERSATION MEMORY
----------------------------------------------------

If the user asks:

"Why?"

"What changed?"

"What are you waiting for?"

The avatar should answer using its session memory.

Example:

"I'm still waiting because twenty seconds ago we failed to reclaim VWAP. Since then buyers have improved, but structure still isn't confirmed."

Do not recalculate anything.

Use stored observations.

----------------------------------------------------
7. THOUGHT EVOLUTION
----------------------------------------------------

Ambient thoughts should evolve naturally.

Instead of repeating:

"Watching buyers."

Progress through observations like:

"Watching buyers."

↓

"Buyers are becoming more active."

↓

"They're starting to defend."

↓

"This is becoming interesting."

↓

"I still need confirmation."

Avoid repetitive wording.

----------------------------------------------------
8. UNCERTAINTY
----------------------------------------------------

The avatar should acknowledge uncertainty.

Examples:

"I like this setup, but I'd prefer stronger volume."

"This qualifies, although it isn't today's strongest opportunity."

"I'm interested, but I'd still be cautious."

Never sound overconfident.

Never guarantee outcomes.

----------------------------------------------------
9. MARKET TIMELINE
----------------------------------------------------

Maintain a lightweight timeline of important observations.

Examples:

09:31
Watching buyers.

09:34
VWAP reclaimed.

09:36
Structure improved.

09:38
Confidence increased.

09:40
READY.

Use this timeline internally for better explanations.

Do not expose it unless requested.

----------------------------------------------------
10. NATURAL LANGUAGE
----------------------------------------------------

Responses should sound like an experienced trader.

Avoid repetitive phrases.

Vary wording naturally.

Examples:

"I'm becoming more interested."

"This is developing nicely."

"I'd still wait."

"This isn't convincing."

"I'm losing interest."

"I'd rather be patient."

----------------------------------------------------
11. SPEECH POLISH
----------------------------------------------------

Never interrupt an explanation midway.

High-priority events may replace low-priority ambient thoughts.

Avoid repeating nearly identical messages.

Track recently spoken concepts.

----------------------------------------------------
12. PERFORMANCE
----------------------------------------------------

Use only existing polling.

Reuse existing diagnostics.

Reuse existing confidence.

Reuse existing market state.

No additional polling.

No API requests.

No backend work.

Memory should remain lightweight.

----------------------------------------------------
SUCCESS CRITERIA
----------------------------------------------------

The avatar should no longer feel like a notification system.

It should feel like a professional trading partner sitting beside the user, continuously observing the market, remembering what it has seen, explaining how its opinion evolves, answering follow-up questions with context, and telling the story of the market throughout the session.

The trading engine must remain completely unchanged and all existing trading validation tests must continue to pass unchanged.
