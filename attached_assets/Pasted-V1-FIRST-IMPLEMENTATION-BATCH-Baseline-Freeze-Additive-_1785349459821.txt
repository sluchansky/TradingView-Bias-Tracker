STAGE 2 — ADD VERSION METADATA

Implement roadmap tasks V1-P1-001 through V1-P1-007.

Required Change

Add the specified interface-version field to the canonical output of each component.

Expected conceptual result:

{
    "_version": "v1",
    # existing fields remain unchanged
}

The Left Brain contract must use its documented version:

{
    "_version": "v2",
    # existing fields remain unchanged
}

These examples are conceptual only.

Follow the existing language, object style, serialization pattern, and architecture contract in the repository.

Additive-Only Requirement

For every interface:

* Add exactly one version field at the canonical boundary.
* Preserve every existing field.
* Preserve every existing field value.
* Preserve existing field types.
* Preserve existing defaults.
* Preserve existing ordering where golden tests or serialized comparisons depend on ordering.
* Preserve exception handling.
* Preserve logging.
* Preserve side effects.
* Preserve callers.
* Preserve operator output unless the interface is intentionally exposed there.
* Preserve byte-level output where possible except for the new field.

Do not make version metadata conditional.

Do not derive it dynamically from Git commits, application releases, environment variables, timestamps, or deployment revisions.

The interface version must represent the contract version, not the software build version.

STOP CONDITIONS

Stop and report without continuing if:

* The initial baseline is not green.
* The seven canonical interfaces cannot be identified confidently.
* The architecture documents conflict about the version field.
* Adding a field requires a database migration not authorized by the roadmap.
* A broker payload rejects unknown fields and the version would cross the broker boundary.
* A version field changes a signature used by external integrations.
* A primary regression fails after the changes.
* Verdicts, scores, trade direction, sizing, or execution behavior change.
* Databento-related files appear in the task diff.
* The task would require a production deployment to prove basic correctness.
* HEAD changes unexpectedly during the task and the change is not clearly attributable to the work being performed.

Do not work around a stop condition silently.
