TASK: Revise the Journal/Tradzella import design so internal strategy attribution is preserved automatically.

PROBLEM

Tradzella exports often do not include the actual system strategy or setup unless the operator manually enters it.

Therefore, Tradzella cannot be treated as the source of truth for:

- strategy
- setup
- playbook
- thesis
- Edge Score
- readiness
- confirmations
- blockers
- planned risk

GOAL

Use the AI Trading Partner as the canonical source for decision context and strategy identity.

Use Tradzella primarily as a source for execution and outcome data.

The Journal must merge both sources into one complete trade record.

STRICT SCOPE

Do not modify:

- strategy calculations
- Edge Score
- readiness
- Databento
- TradersPost execution
- risk rules
- learning formulas
- polling
- authentication

PART 1 — CAPTURE AN INTERNAL TRADE SNAPSHOT

At the moment a trade is sent, simulated, manually confirmed, or otherwise registered, persist an immutable trade-context snapshot.

Required fields:

- internal_trade_id
- signal_id
- execution_fingerprint
- instrument
- contract
- account
- mode
- direction
- canonical_strategy_key
- strategy_display_name
- setup_name
- playbook
- thesis_direction
- thesis_strength
- thesis_alignment
- Edge Score
- grade
- readiness
- actionable
- confirmations
- blockers
- opposing_structure
- risk_state
- planned_entry
- planned_stop
- planned_targets
- planned_risk
- planned_contracts
- created_at
- sent_at
- source

Do not reconstruct these values later from current market state.

PART 2 — SOURCE-OF-TRUTH OWNERSHIP

Use these ownership rules:

INTERNAL SYSTEM OWNS

- strategy
- setup
- playbook
- thesis
- Edge Score
- readiness
- confirmations
- blockers
- planned risk
- signal identity

TRADZELLA / BROKER IMPORT OWNS

- actual fills
- actual quantity
- actual entry price
- actual exit price
- commissions
- fees
- gross P&L
- net P&L
- open time
- close time
- duration
- broker trade ID

OPERATOR OWNS

- notes
- screenshots
- mistake tags
- emotion tags
- followed-plan review
- lesson learned
- manual strategy assignment for unmatched trades

PART 3 — TRADE MATCHING

When importing Tradzella rows, attempt deterministic matching against internal trade snapshots.

Matching priority:

1. exact external order/trade ID
2. exact internal signal or fingerprint reference, if preserved
3. account + instrument + direction + quantity + entry-time window
4. account + instrument + direction + entry price + entry-time window
5. manual review

Do not fuzzy-match strategy names.

Do not assign a strategy merely because it is the closest recent setup.

PART 4 — MATCH CONFIDENCE

Every imported trade must receive:

- MATCHED_EXACT
- MATCHED_HIGH_CONFIDENCE
- MATCHED_LOW_CONFIDENCE
- UNMATCHED
- AMBIGUOUS

Store:

- matched_internal_trade_id
- match_method
- match_confidence
- candidate_count
- match_notes

Low-confidence and ambiguous matches must require operator review before becoming learning-eligible.

PART 5 — UNMATCHED TRADE REVIEW

Create a NEEDS REVIEW queue.

For unmatched or ambiguous Tradzella trades, allow the operator to assign:

- strategy
- setup
- playbook
- mode
- direction confirmation
- whether it was system-generated
- whether it should be learning-eligible

Clearly label manually assigned strategy attribution.

Do not pretend it was captured automatically.

PART 6 — MERGE WITHOUT OVERWRITING

When a Tradzella row matches an internal snapshot:

Preserve internal:

- strategy
- thesis
- score
- readiness
- planned values

Add imported:

- actual fills
- actual outcome
- commissions
- P&L

Never let an empty Tradzella strategy field overwrite a valid internal strategy.

Never let a later import overwrite reviewed notes or screenshots.

PART 7 — TRADERSPOST LINKAGE

Audit whether the existing TradersPost send path returns or records:

- order ID
- signal ID
- webhook payload ID
- timestamp
- ticker
- direction
- quantity

Where possible, persist these values in the internal trade snapshot to improve future Tradzella matching.

Do not change TradersPost payload semantics unless required and proven safe.

PART 8 — MANUAL TRADES

For trades entered outside the system:

- import normally
- mark source as EXTERNAL_MANUAL
- require strategy/setup review
- default learning status to REVIEW_REQUIRED

Do not force them into a system strategy automatically.

PART 9 — LEARNING SAFETY

A Tradzella-imported trade may become learning-eligible only when:

- trade is closed
- execution data is valid
- not a duplicate
- strategy identity is exact or operator-confirmed
- planned risk is known
- outcome is normalized
- match is not ambiguous
- review is complete

Unmatched imports must not alter learning weights.
