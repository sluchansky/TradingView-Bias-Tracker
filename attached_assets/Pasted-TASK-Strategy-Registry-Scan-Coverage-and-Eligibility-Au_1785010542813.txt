PART 4 — DISTINGUISH SCANNED FROM SELECTED
----------------------------------------------------

Add diagnostics that distinguish these states:

- registered
- enabled
- eligible
- evaluated
- skipped
- no_signal
- candidate
- selected
- rejected_after_selection
- error

A strategy must not be marked "scanned" merely because it exists in the registry.

A strategy counts as evaluated only if its evaluation function was actually
called for that instrument, direction, mode, and cycle.

For every evaluation cycle, diagnostics should support an entry like:

{
    "strategy_key": "liquidity_sweep_reversal",
    "registered": true,
    "enabled": true,

    "selected": false,
    "skip_reason": null,
    "evaluation_ms": 1.7
}

    "registered": true,
    "enabled": true,
    "eligible": false,
    "evaluated": false,
    "result": "skipped",
    "selected": false,
    "skip_reason": "outside_session",

}

Diagnostics only.
