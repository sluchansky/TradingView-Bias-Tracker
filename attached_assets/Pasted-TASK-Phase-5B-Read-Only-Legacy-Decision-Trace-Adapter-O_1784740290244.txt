TASK: Phase 5B — Read-Only Legacy Decision Trace Adapter

OBJECTIVE

Create a read-only decision trace from the final existing full_analysis() result.

This phase is observability only.

DO NOT change:

* Verdict behavior
* Scoring
* Thresholds
* Strategy selection
* Setup gates
* Veto ordering
* Risk checks
* Trade plans
* Auto execution
* Manual execution
* Alerts
* Active trade management
* Database behavior
* The public /status response
* The existing Brain Contract

CORE RULE

The adapter must describe the decision that the legacy system already made.

It must not create a second decision engine.

REQUIREMENTS

1. Add a pure function named:

build_legacy_decision_trace(result, instrument, generated_at=None)

2. The function must use only:

* The completed full_analysis result
* Already-computed fields contained in that result
* Explicitly supplied arguments

3. The function must not:

* Call full_analysis()
* Call evaluate_strict_setup()
* Call generate_trade_plan()
* Call build_strict_trade_plan()
* Call any broker or TradersPost function
* Call any network request
* Fetch yfinance data
* Read or write the database
* Mutate global dictionaries
* Register duplicate fingerprints
* Update cooldowns
* Update active trades
* Recompute scores
* Re-run veto functions
* Change the result dict supplied to it

4. Return this initial schema:

{
“instrument”: str,
“generated_at”: float,

“legacy”: {
“verdict”: str,
“is_actionable”: bool,
“strict_reason”: str | null
},

“decision”: {
“domain”: “ENTRY” | “MANAGEMENT”,
“state”: “INVALID_DATA” |
“MARKET_CLOSED” |
“MONITOR” |
“SETUP_FORMING” |
“READY” |
“BLOCKED” |
“MANAGE”,
“direction”: “LONG” | “SHORT” | null,
“tier”: “FULL” | “EARLY” | null,
“reason”: str | null,
“next_action”: str | null
},

“setup”: {
“score”: number | null,
“grade”: str | null,
“plan_available”: bool,
“plan_executable”: bool
},

“active_trade”: {
“present”: bool,
“state”: str | null
},

“mapping_warnings”: []
}

5. Mapping requirements:

* LONG READY:
    state = READY
    direction = LONG
    tier = FULL
* SHORT READY:
    state = READY
    direction = SHORT
    tier = FULL
* LONG EARLY READY:
    state = READY
    direction = LONG
    tier = EARLY
* SHORT EARLY READY:
    state = READY
    direction = SHORT
    tier = EARLY
* Market-closed NO TRADE:
    state = MARKET_CLOSED
    Do not map market closure to INVALID_DATA.
* Existing active trade:
    domain = MANAGEMENT
    state = MANAGE
* WAIT or WATCH:
    Use SETUP_FORMING only when the existing result contains clear evidence that a directional setup is forming.
    Otherwise use MONITOR.
* Unknown instrument or explicitly invalid/malformed required data:
    state = INVALID_DATA
* Do not infer BLOCKED_BY_RISK in this phase.
    The legacy result does not yet contain a reliable canonical risk snapshot.

6. Direction must be stored separately from state.

Do not require consumers to parse direction from the verdict after this adapter has produced the trace.

7. Do not use call order to decide the primary reason.

For now:

* Preserve the existing strict_reason as legacy.strict_reason
* Preserve any existing reason arrays if present
* Add a mapping warning when more than one blocking reason exists but priority cannot be determined

8. Exposure

Expose the trace only through the owner-only /diagnostics-live response.

Do not add decision_trace to:

* Public /status
* Brain Contract
* Dashboard polling payload
* Broker payloads
* Discord payloads

9. Feature flag

Add:

DECISION_TRACE_SHADOW_ENABLED

Default: OFF

Behavior:

* OFF:
    No trace computation
    No new response keys
    Existing golden outputs must remain byte-identical
* ON:
    Build the trace only after full_analysis has completed
    Publish it only through owner-only diagnostics
    The trace must not affect any live decision or action

10. Required tests

Add tests proving:

* Flag OFF preserves existing golden output exactly
* Adapter does not mutate its input
* LONG READY maps correctly
* SHORT READY maps correctly
* EARLY READY tier maps correctly
* Market closed maps to MARKET_CLOSED, not INVALID_DATA
* WAIT without directional evidence maps to MONITOR
* WAIT with clear directional forming evidence maps to SETUP_FORMING
* Active trade maps to domain MANAGEMENT and state MANAGE
* Missing plan does not change the legacy verdict
* No decision trace appears in public /status
* Decision trace appears in owner-only /diagnostics-live when enabled
* No broker, database, network, cooldown, or duplicate-guard function is called
* Existing parity, scalp_golden, dual_sim, and breakout_mode tests still pass

DELIVERABLE

Return:

1. Files changed
2. Functions added
3. Exact feature-flag behavior
4. Tests added
5. Test results
6. Confirmation that no trading behavior changed
7. Confirmation that /status and Brain Contract remain unchanged
