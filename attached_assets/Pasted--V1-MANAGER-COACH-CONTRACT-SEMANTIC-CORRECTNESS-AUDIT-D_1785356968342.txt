=========================================================

The current Coach mappings reportedly include:

    LEARNING_ANALYTICS.get("ready", False)

    bool(THESIS_TRACKER_DB_READY)

A field named thesis_resolved must not become true merely because the thesis database is available.

Do not preserve these mappings simply because existing tests pass.

STEP 3 — PROVE AUTHORITATIVE SOURCES
=========================================================

For every Coach field, identify an authoritative value that represents the actual contract meaning.

---------------------------------------------------------
weight_updated
---------------------------------------------------------

Determine whether the codebase has an actual event or result indicating that a strategy weight changed.

Search for:

- the function that writes or changes a learning weight
- return values from weight-update operations
- timestamps or update records
- before/after weight comparisons
- persisted update events
- trade-close learning results

The source must distinguish:

- learning system ready
- learning system enabled
- update attempted
- update skipped
- update failed
- weight actually changed

Do not map readiness, enablement, DB availability, or sample sufficiency to weight_updated.

If no authoritative actual-update value exists, use only the architecture-defined unavailable representation.

If unavailable behavior is undefined, stop.

---------------------------------------------------------
thesis_resolved
---------------------------------------------------------

Determine whether the codebase has an actual thesis resolution event or state.

Search for:

- thesis status transitions
- resolved_at
- resolution outcome
- close or settlement linkage
- thesis tracker update functions
- stored resolved thesis records
- trade-close processing

The source must distinguish:

- thesis database ready
- thesis exists
- thesis active
- thesis expired
- thesis invalidated
- thesis actually resolved

Do not map THESIS_TRACKER_DB_READY to thesis_resolved.

If no authoritative resolution value exists, use only the documented unavailable representation.

---------------------------------------------------------
learning_influence
---------------------------------------------------------

Confirm the exact required type and shape.

Determine whether the canonical value is:

- the complete learning influence object
- a direction-specific delta
- a numeric scalar
- a boolean
- a structured eligibility and reason object

Do not compress the authoritative object to only Long/Short deltas unless the architecture explicitly requires that representation.

Do not recompute influence.

---------------------------------------------------------
rule_engine_eligibility
---------------------------------------------------------

Confirm whether calling:

_check_learning_eligibility(instrument, mode)

is acceptable for a read-only aggregation contract.

Prove:

- the function has no writes
- no counters are changed
- no timestamps are changed
- no logs with stateful throttling are changed
- no learning update is triggered
- no live gate is changed
- no database mutation occurs
- no expensive or duplicate decision computation is introduced

Also confirm the contract requires the function’s boolean result rather than its complete reason or metadata object.

If calling the function reruns business logic rather than reading existing authoritative state, replace it with an existing result already computed in the normal pipeline.

Do not introduce a second eligibility calculation.
