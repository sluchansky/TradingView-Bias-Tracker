GOAL

Do NOT allow it to drive production READY, alerts, risk, execution, or TradersPost yet.

==================================================
PART 1 — DEFINE TWO SETUP FAMILIES
==================================================

Support:

1. FVG_CONTINUATION
2. IFVG_REVERSAL

Do not treat every zone interaction as the same setup.

==================================================
PART 2 — FVG CONTINUATION SEQUENCE
==================================================

For bullish continuation:

BULLISH FVG CREATED
→ PRICE RETURNS
→ FVG TOUCHED
→ FVG HOLDS
→ BULLISH STRUCTURE CONFIRMS AFTER TOUCH
→ MOMENTUM RETURNS
→ ENTRY WINDOW

Mirror for bearish.

Required sequence states:

FVG_CREATED
RETURN_PENDING
TOUCHED
HOLD_PENDING
HOLD_CONFIRMED
STRUCTURE_PENDING
MOMENTUM_PENDING
ENTRY_WINDOW
SHADOW_READY
EXPIRED
INVALIDATED

Important:

A BOS/CHOCH that happened before the FVG touch cannot satisfy post-touch confirmation.

All confirming events must belong to the active sequence.

==================================================
PART 3 — IFVG REVERSAL SEQUENCE
==================================================

For bullish IFVG reversal:

BEARISH FVG
→ PRICE INVALIDATES ABOVE IT
→ BEARISH FVG = INVERTED
→ BULLISH IFVG CREATED
→ PRICE RETESTS IFVG FROM ABOVE
→ IFVG HOLDS
→ BULLISH STRUCTURE CONFIRMS
→ MOMENTUM CONFIRMS
→ ENTRY WINDOW

Mirror for bearish.

Sequence states:

ORIGINAL_FVG
INVERSION_PENDING
INVERTED
RETEST_PENDING
RETESTED
HOLD_PENDING
HOLD_CONFIRMED
STRUCTURE_PENDING
MOMENTUM_PENDING

EXPIRED
INVALIDATED

==================================================
PART 5 — POST-TOUCH STRUCTURE CONFIRMATION
==================================================

Audit the existing canonical structure events.

Use only events occurring AFTER:

- FVG touch for continuation
- IFVG retest for inversion

Accept only the appropriate directional structure event.

For Long:

- bullish BOS and/or bullish CHOCH according to existing canonical semantics

For Short:

- bearish BOS and/or bearish CHOCH

Do not require both unless current strategy rules explicitly require both.

Do not reuse stale events.

==================================================
PART 6 — MOMENTUM CONFIRMATION
==================================================

Build a transparent momentum object from existing canonical data.

Candidate evidence:

- displacement relative to ATR
- strong directional close
- consecutive directional closes
- CVD/delta agreement
- volume expansion
- structure break
- movement away from the zone

Example:

{
  "direction": "LONG",
  "confirmed": true,
  "checks": {
    "displacement": true,
    "close_strength": true,
    "cvd": false,
    "volume": true,
    "structure": true
  },
  "confirmed_count": 4,
  "required_count": 3,
  "confirmed_at": "..."
}

Do not create an opaque confidence score.

Use explicit checks.

==================================================
PART 7 — ENTRY WINDOW
==================================================

Once structure + momentum confirm, open a limited SHADOW entry window.

Track:

- opened_at
- confirmation_price
- current_price
- age_seconds
- distance_from_zone
- distance_moved_since_confirmation
- ATR distance
- target_consumed_percent

Classify:

ENTRY_AVAILABLE
ENTRY_LATE
ENTRY_CHASING
ENTRY_EXPIRED

Only ENTRY_AVAILABLE may become SHADOW_READY.

Do not send any trade.

==================================================
PART 10 — MULTIPLE ZONES
==================================================

An instrument may have multiple active FVGs.

Rules:

- multiple zones can remain tracked
- only the highest-ranked valid sequence per direction becomes PRIMARY
- secondary sequences remain visible
- overlapping zones must not produce duplicate READY candidates
- same zone cannot own multiple active identical sequences

==================================================
PART 11 — EXPIRATION
==================================================

Sequences must expire.

Use deterministic conditions based on existing data, such as:

- zone expired
- sequence age exceeded configured limit
- price moved too far
- target mostly consumed
- opposite structure invalidated setup
- another stronger sequence superseded it
- session ended

Do not leave stale sequences permanently in MOMENTUM_PENDING.
