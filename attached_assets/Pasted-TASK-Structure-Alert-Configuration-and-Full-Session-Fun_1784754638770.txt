TASK: Structure Alert Configuration and Full-Session Funnel Verification

OBJECTIVE

Determine whether BOS, CHOCH, and swing-structure alerts are:

1. Not configured in TradingView
2. Configured incorrectly
3. Configured but failing to reach production
4. Reaching production under unexpected names
5. Correctly configured but simply not triggering
6. Triggering but expiring or being overwritten before decision evaluation

Do not change the hard structure gate yet.

IMPORTANT CORRECTION TO THE PREVIOUS AUDIT

The previous audit covered approximately 14 minutes near the futures daily maintenance window.

That sample proves:

* Structure alerts were almost absent during that window
* The decision engine requires structure
* Missing structure caused WAIT during those evaluations

It does not yet prove:

* Structure alerts are permanently absent
* TradingView configuration is wrong
* The hard structure gate should be removed
* Structure is the only problem across an active trading session

Do not call structure the sole root cause until the checks below are complete.

PHASE 10 — DECISION RULES

Use the following decision framework after gathering the evidence.

CASE A — STRUCTURE ALERTS ARE NOT CONFIGURED

Recommendation:

* Create and activate the correct TradingView structure alerts
* Match production’s exact accepted payload contract
* Do not alter engine thresholds

CASE B — ALERTS ARE CONFIGURED BUT PAYLOAD NAMES DO NOT MATCH

Recommendation:

* Correct the TradingView messages or add safe parser aliases
* Preserve existing accepted names
* Add parser tests for every configured message

CASE C — ALERTS REACH PRODUCTION BUT EXPIRE TOO QUICKLY

Recommendation:

* Adjust structure TTL only after comparing it with bar timeframe
* Prevent stale structure from appearing current
* Add explicit structure age to decision traces

CASE D — ALERTS ARE CORRECT AND GENUINELY RARE

Recommendation:

* Do not immediately remove the structure gate
* Measure READY frequency over multiple active sessions
* Consider an EARLY or SETUP FORMING state that reports partial confluence without authorizing a trade

CASE E — STRUCTURE IS PRESENT BUT THE ENGINE STILL SAYS MISSING

Recommendation:

* Fix cache namespace, timeframe, direction, or consumer lookup
* Add an end-to-end regression test using a real production payload
