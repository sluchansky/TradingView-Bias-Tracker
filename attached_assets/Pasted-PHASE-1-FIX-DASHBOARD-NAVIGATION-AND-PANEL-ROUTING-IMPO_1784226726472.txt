PHASE 1: FIX DASHBOARD NAVIGATION AND PANEL ROUTING

IMPORTANT:
Do not change trading logic, alerts, scoring, webhooks, auto-trading, backend calculations, or database behavior.

This phase is only for fixing the top navigation pills and separating the dashboard into real sections.

GOAL:
The existing pills:

OVERVIEW
BRAIN
ANALYSIS
JOURNAL
CONTROLS

must behave as actual dashboard sections.

REQUIREMENTS:

1. Only one section may be active at a time.

2. Clicking a pill must render only the panels assigned to that section.

3. The selected pill must remain clearly highlighted.

4. Add a visible section heading directly below the pills.

Example:

BRAIN selected

Heading:
BRAIN

Visible content:
Only Brain panels

5. Do not make the pills simply scroll to content.

6. Do not leave every panel rendered underneath the selected section.

7. Preserve current instrument, sensitivity, alert, and trading-control state when switching sections.

8. Save the selected section in localStorage so it remains selected after refresh.

Use this section structure:

type DashboardSection =
  | "overview"
  | "brain"
  | "analysis"
  | "journal"
  | "controls";

9. Add accessibility support:

- aria-selected="true" on the active pill
- keyboard navigation between pills
- visible focus state

10. Active pill styling:

- brighter or filled background
- accent border
- high-contrast text
- optional subtle glow

Inactive pills:

- darker background
- muted text
- no glow

11. Mobile requirements:

- pills may scroll horizontally
- selected pill must remain visible
- no page-level horizontal overflow
- one-column layout
- no clipped pill text
