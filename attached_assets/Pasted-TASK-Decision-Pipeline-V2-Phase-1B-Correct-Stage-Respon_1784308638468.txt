OBJECTIVE

Refine the existing Decision Pipeline V2 so each stage has one clear responsibility.

Do not add new strategies.
Do not add new indicators.
Do not change live trading behavior.
Do not change production confidence.
Do not change risk.
Do not change position sizing.

==================================================
1. CORRECT THE 5-STAGE RESPONSIBILITIES
==================================================

The pipeline must operate in this order:

1. OBSERVE
2. INTERPRET
3. PRIORITIZE
4. VALIDATE
5. DECIDE

Each stage must answer a different question.

--------------------------------------------------
STAGE 1: OBSERVE
--------------------------------------------------

Question:

What facts are currently available?

Collect existing:

- Price
- VWAP
- CVD
- Volume
- ATR
- Market structure
- Prior-day levels
- Recent alerts
- Existing news-panel data
- Sector data
- Account state
- Position state
- Prop-rule state
- Data freshness

Do not classify the market here.

Do not create a directional bias here.

Do not rank markets here.

Do not produce a trade verdict here.

--------------------------------------------------
STAGE 2: INTERPRET
--------------------------------------------------

Question:

What type of market environment is present, and what appears to be driving it?

This stage must not produce LONG or SHORT trade instructions.

Create or update:

market_interpretation

Required fields:

{
  "regime": "RISK_OFF",
  "regime_confidence": 82,
  "primary_driver": "GEOPOLITICAL",
  "secondary_drivers": [
    "ENERGY"
  ],
  "risk_state": "DEFENSIVE",
  "dominant_theme": "SAFE_HAVEN_DEMAND",
  "supporting_evidence": [],
  "conflicting_evidence": [],
  "data_quality": "MODERATE"
}

Allowed regime values:

- RISK_ON
- RISK_OFF
- NEUTRAL
- MIXED
- UNKNOWN

Allowed driver values:

- GEOPOLITICAL
- FED_POLICY
- INFLATION
- EMPLOYMENT
- ECONOMIC_GROWTH
- EARNINGS
- ENERGY
- LIQUIDITY
- TECHNICAL
- MULTIPLE
- NONE
- UNKNOWN

Critical rule:

The regime describes what the market is doing.

The driver explains why it is doing it.

Correct:

Regime: RISK_OFF
Primary driver: GEOPOLITICAL

Incorrect:

Regime: GEOPOLITICAL

Do not resolve classification conflicts by enum ordering.

Do not output long, short, buy, sell, approve, or reject from this stage.

--------------------------------------------------
STAGE 3: PRIORITIZE
--------------------------------------------------

Question:

Which existing traded markets deserve the most attention in this environment?

Rank only supported instruments such as:

- MNQ
- MES
- MYM
- MGC

This stage may assign contextual direction, but it must not create a trade.

Example:

{
  "symbol": "MGC",
  "priority": 1,
  "preference": "FAVORED",
  "directional_context": "BULLISH",
  "context_confidence": 74,
  "reasons": [
    "Risk-off regime",
    "Safe-haven demand",
    "Gold above VWAP"
  ],
  "conflicts": [
    "Dollar strength"
  ]
}

Allowed preference values:

- STRONGLY_FAVORED
- FAVORED
- NEUTRAL
- DISFAVORED
- STRONGLY_DISFAVORED
- INSUFFICIENT_DATA

Rules:

- Priority is not a trade command.
- Directional context is not an APPROVE verdict.
- A disfavored market may still contain a valid technical setup.
- Do not block markets solely because of ranking.
- Do not route orders from this stage.

--------------------------------------------------
STAGE 4: VALIDATE
--------------------------------------------------

Question:

Does an actual technical setup exist, and does it pass all safety rules?

Reuse the existing production logic for:

- Structure
- VWAP
- CVD
- Trend
- Liquidity sweep
- CHOCH
- BOS
- FVG
- Order blocks
- Zone freshness
- ATR
- Reward-to-risk
- Volatility
- Prop rules
- Daily loss limits
- FLAT checks
- Working-order checks
- Instrument verification
- Position sizing

Do not duplicate or rewrite existing strategy logic.

Create:

technical_validation

Example:

{
  "symbol": "MGC",
  "strategy": "EXISTING_STRATEGY",
  "technical_status": "WAIT",
  "technical_confidence": 81,
  "passed_checks": [],
  "failed_checks": [
    "Fresh demand-zone retest missing"
  ],
  "risk_checks": {},
  "account_checks": {},
  "production_verdict": "WAIT"
}

This is the first stage where setup direction may be technically validated.

--------------------------------------------------
STAGE 5: DECIDE
--------------------------------------------------

Question:

Given the environment, market priority, technical setup, and risk checks, what is the final shadow conclusion?

Create:

decision_pipeline_v2_result

Example:

{
  "symbol": "MGC",
  "market_regime": "RISK_OFF",
  "primary_driver": "GEOPOLITICAL",
  "market_priority": "FAVORED",
  "directional_context": "BULLISH",
  "technical_verdict": "WAIT",
  "production_verdict": "WAIT",
  "shadow_verdict": "WAIT",
  "agreement_status": "AGREE",
  "changed_production_behavior": false,
  "explanation": {
    "what_is_happening": "The market is risk-off.",
    "why_it_is_happening": "Geopolitical escalation appears to be the primary driver.",
    "why_this_market_is_relevant": "Gold is showing safe-haven strength.",
    "what_the_technical_engine_found": "MGC is above VWAP but has not completed a fresh demand-zone retest.",
    "what_must_happen_next": "Wait for a valid retest and renewed structure confirmation.",
    "what_invalidates_the_idea": "Loss of bullish structure and a sustained move below VWAP."
  },
  "shadow_mode": true
}

The shadow verdict must not affect production behavior.

}

Possible better-decision values:

- PRODUCTION
- V2
- BOTH
- NEITHER
- INCONCLUSIVE

Examples:

Trade stops out

Production APPROVE
V2 WAIT

V2 was more correct.

BOTH.

Both APPROVE
