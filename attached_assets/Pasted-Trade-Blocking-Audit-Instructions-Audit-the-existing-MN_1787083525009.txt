Trade Blocking Audit Instructions

Audit the existing MNQ trading system to determine exactly what is preventing SCALP and INTRADAY_TREND trades from progressing to READY / execution.

Do not change any live trading thresholds, gates, strategy logic, risk rules, or execution behavior during this audit. This phase is read-only analysis plus reporting unless a logging gap must be fixed to make the audit possible.

Scope

Audit both:

* SCALP
* INTRADAY_TREND

For SCALP, preserve the individual strategy/setup identity. Do not combine all scalp strategies into one bucket.

Use the existing gate effectiveness / ghost trade / research data wherever possible.

1. Build the Opportunity Funnel

For each mode, calculate:

evaluated opportunities → setup detected → qualified → plan built → READY → execution requested → traded → closed

Show counts and percentages at every stage.

Also show where opportunities disappear from the pipeline.

2. Rank Every Blocking Gate

For each mode and strategy/setup, report every gate that prevented progression.

For each gate capture:

* gate name
* mode
* strategy
* setup_id
* LONG / SHORT
* timestamp
* current market session
* whether it was the first blocking gate
* whether other gates also failed
* number of total blocks
* percentage of all blocked opportunities

Rank gates from most restrictive to least restrictive.

3. Evaluate What Happened After Every Block

For every blocked opportunity with enough market data afterward, calculate the hypothetical trade outcome using the geometry already stored by the system.

Measure:

* entry
* stop
* TP1
* TP2
* max favorable excursion
* max adverse excursion
* R achieved
* whether TP1 would have hit
* whether TP2 would have hit
* whether stop would have hit
* whether neither occurred before expiration
* time to TP1
* time to stop

Do not invent geometry when reliable geometry cannot be reconstructed. Mark those records clearly as NO_GEOMETRY.

4. Calculate False-Block Rate

For every blocking gate calculate:

false-block rate = blocked opportunities that would have produced a winning hypothetical trade / blocked opportunities with valid outcomes

Also calculate:

* average hypothetical R
* median hypothetical R
* total hypothetical R prevented
* total hypothetical losses avoided
* TP1 hit rate
* TP2 hit rate
* stop rate

This is the core question:

Is this gate protecting the account, or blocking profitable trades?

5. Audit Gate Combinations

Do not only evaluate gates individually.

Find the most common combinations, for example:

VWAP + LOCATION

STRUCTURE + VWAP

LOCATION + VOLATILITY

VWAP + STRUCTURE + CANDLE

For each combination calculate the same hypothetical outcome statistics.

Determine whether a gate appears harmful only when isolated, but useful when combined with another gate.

6. Segment by Time of Day

Use Eastern Time.

At minimum create these buckets:

* 05:00–08:00
* 08:00–09:30
* 09:30–10:30
* 10:30–12:00
* 12:00–14:00
* 14:00–15:45
* 15:45–16:00
* 16:00–17:00
* overnight / remaining session

Treat 15:45–16:00 and 16:00–17:00 as independent regimes.

Do not merge them into the normal afternoon statistics.

For each time bucket show:

* opportunities
* blocks
* READY trades
* win rate
* hypothetical blocked-trade win rate
* average R
* most common blocking gate

7. Segment by Market Context

Where data exists, also split results by:

* LONG vs SHORT
* above vs below VWAP
* trend vs range
* aligned vs conflicted higher timeframe structure
* normal vs elevated vs extreme volatility
* proximity to day high
* proximity to day low
* opening range context
* premarket high/low context

Do not create new trading rules from these fields yet. This is analysis only.

8. SCALP Strategy-Level Audit

For every existing scalp strategy/setup report separately:

* opportunities detected
* READY count
* blocked count
* top blocking gates
* hypothetical blocked win rate
* live/shadow win rate if available
* average R
* expectancy
* profit factor where sample size is sufficient

Identify strategies that are producing opportunities but almost never surviving the shared SCALP gates.

This is especially important because a good individual strategy may currently be getting killed by generic shared gating.

9. Gate Classification

After the statistics are complete, classify each gate as one of:

KEEP HARD

SOFTEN CANDIDATE

CONTEXT-DEPENDENT

REMOVE CANDIDATE

INSUFFICIENT DATA

Do not actually change the gate.

The classification must be supported by data, not opinion.

Example reasoning:

KEEP HARD:
Gate blocks many losing trades and has low false-block rate.

SOFTEN CANDIDATE:
Gate blocks a high percentage of eventual winners and prevents positive net hypothetical R.

CONTEXT-DEPENDENT:
Gate works well in one regime but badly in another.

REMOVE CANDIDATE:
Gate consistently destroys positive expectancy with little protective value.

INSUFFICIENT DATA:
Sample size too small.

11. Special Attention: 15:45–17:00 ET

Explicitly investigate:

15:45–16:00:

* closing drive continuation
* closing reversal
* day-high/day-low sweeps
* VWAP extension
* trend acceleration

16:00–17:00:

* post-cash-close continuation
* mean reversion
* reduced liquidity
* fake breakouts
* abnormal wick behavior
* whether SCALP gates behave differently in this regime

Report whether these windows should eventually:

* use normal SCALP rules
* use modified rules
* be research-only
* be blocked entirely

Do not implement that decision yet.

12. Data Quality Audit

Before trusting conclusions, verify:

* observations are actually closing
* MFE/MAE backfill is functioning
* timestamps use correct ET conversion
* strategy/setup_id is populated
* SCALP and IT records are not mixed incorrectly
* expired observations are not counted as losses
* duplicate opportunities are not inflating counts
* NO_GEOMETRY records are reported separately
* post-restart observations continue completing correctly

If any of these are broken, fix only the instrumentation/data collection issue necessary for the audit, then rerun the analysis.

13. Minimum Sample Warnings

Do not make strong recommendations from tiny samples.

Show sample-size warnings for:

* n < 20: very low confidence
* n 20–49: low confidence
* n 50–99: moderate
* n ≥ 100: stronger evidence

Never recommend removing a major safety gate from fewer than 50 valid hypothetical outcomes.

6. Gate-combination analysis
7. SCALP strategy-by-strategy analysis
8. INTRADAY_TREND analysis
9. Time-of-day analysis including 15:45–16:00 and 16:00–17:00
10. Final gate classifications
11. Top 5 highest-value changes to test next

Do not implement the Top 5 changes.
