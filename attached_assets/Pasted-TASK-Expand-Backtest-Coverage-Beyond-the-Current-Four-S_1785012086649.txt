TASK: Expand Backtest Coverage Beyond the Current Four Strategies

CRITICAL CONTEXT

The backtest dashboard already supports:

- All-strategy selection
- Per-strategy ranking
- Tradable status
- Trade counts
- Win rate
- Profit factor
- Net R
- Drawdown
- Losing-trade reasons
- Equity curves
- Trade-log filtering

Do not redesign this UI.

The current problem is that every asset and mode appears to test only these four strategies:

- Liquidity Sweep Reversal
- Range Expansion Breakout
- VWAP Trend Continuation
- Opening Drive

The project may contain many more live strategies.

OBJECTIVE

Determine which additional live strategies can be honestly replayed using the existing historical dataset, then add only those strategies to the backtesting engine.

Do not fabricate inputs.
Do not approximate unavailable Databento data.
Do not change live strategy behavior.
Do not change scoring or execution.

PART 1 — INVENTORY

Find every live strategy.

For each strategy document:

- Strategy key
- Defining function/class
- Live registry status
- Mode eligibility
- Instrument eligibility
- Required inputs
- Historical equivalents available?
- Existing backtest adapter?
- Safe to backtest now?
- Reason if not

PART 2 — CLASSIFY REPLAY SUPPORT

Classify every strategy into:

A. Fully replayable now

All required inputs already exist in the historical dataset.

B. Replayable with deterministic reconstruction

Inputs can be reconstructed without look-ahead using existing bars or stored events.

C. Not honestly replayable yet

Requires unavailable tick, order-book, event-timing, or live-only state.

Examples of unsafe missing inputs may include:

- Tick-level aggressor flow
- Historical Databento CVD unavailable in the dataset
- Order-book imbalance
- Confirmation-alert arrival timing
- Live-only learning state
- Future-known structure labels
- Intrabar sweep ordering not recoverable from bars

Do not add Category C strategies.

PART 3 — TRACE CURRENT FOUR

Identify exactly why only four strategies are currently available.

Return:

- Registry or list
- File and function
- Whether these are adapters separate from the live engine
- Whether the limitation is intentional
- Which historical inputs each current strategy uses

PART 4 — ADD SAFE STRATEGIES

For every Category A strategy:

- Reuse the real strategy logic when possible
- Otherwise create a thin historical adapter
- Preserve entry conditions
- Preserve direction
- Preserve session requirements
- Preserve stop/target logic
- Prevent look-ahead bias
- Prevent future-bar leakage

For Category B strategies:

Do not implement automatically.

Return a proposed reconstruction design and wait for approval unless the reconstruction is already established elsewhere in the codebase and covered by tests.

PART 5 — UI

Do not redesign the backtest dashboard.

Extend the existing Strategy dropdown and ranking table to include newly supported strategies.

Keep existing:

- All strategies option
- Per-strategy filter
- Ranking behavior
- Trade logs
- Equity curves
- Losing-trade explanations
- Tradable qualification

Add a small coverage line only:

Backtest supported: X of Y live strategies

Optionally show unsupported strategies and reasons in a diagnostics drawer.

PART 6 — TESTS

For every added strategy prove:

1. It is invoked in All Strategies mode.
2. It can be selected individually.
3. It receives only historical data available at that timestamp.
4. It does not access future bars.
5. It does not make live Databento calls.
6. It does not use current production state.
7. Its trades appear in ranking and trade log.
8. Existing four-strategy results remain unchanged.
9. Live strategy selection remains unchanged.
10. Production scores and verdicts remain unchanged.

Add a golden fixture for at least one known setup per newly supported strategy.

PART 7 — REPORT

Return:

1. Actual live strategy count
2. Existing backtest strategy count
3. Category A strategies
4. Category B strategies
5. Category C strategies
6. Strategies added
7. Strategies intentionally not added
8. Inputs required by each excluded strategy
9. Files changed
10. Focused test results
11. Full regression results
12. Proof existing four-strategy results did not change
13. Proof live trading behavior did not change

STOP CONDITIONS

Stop and report before implementation if:

- The live strategy logic cannot be separated safely from production state
- Historical data lacks required inputs
- Adding a strategy would require fabricated signals
- Look-ahead bias cannot be prevented
- Existing four-strategy results change
- HEAD changes unexpectedly
- Existing tests fail

MAKE ONLY THIS CHANGE.
