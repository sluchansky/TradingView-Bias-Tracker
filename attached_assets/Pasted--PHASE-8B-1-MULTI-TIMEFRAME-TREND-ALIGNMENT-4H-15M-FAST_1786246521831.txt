# PHASE 8B.1 — MULTI-TIMEFRAME TREND ALIGNMENT

## 4H + 15M — FAST OPERATOR VISIBILITY

Add a very simple multi-timeframe trend-status system to the existing trading dashboard.

Primary focus is MNQ, but preserve the existing multi-instrument architecture.

DO NOT change strategy qualification, execution, scoring, risk, ghost trading, Edge Ledger calculations, or learning behavior.

This phase is INFORMATIONAL ONLY.

---

# OBJECTIVE

Within a few seconds I must be able to answer:

1. Is MNQ trending UP, DOWN, or NEUTRAL on the 4-hour timeframe?
2. Is MNQ trending UP, DOWN, or NEUTRAL on the 15-minute timeframe?
3. Are those two timeframes ALIGNED or CONFLICTING?

Example display:

4H     ↑ BULLISH
15M    ↑ BULLISH
ALIGNMENT     ✅ ALIGNED LONG

or:

4H     ↑ BULLISH
15M    ↓ BEARISH
ALIGNMENT     ⚠ CONFLICTING

or:

4H     — NEUTRAL
15M    ↑ BULLISH
ALIGNMENT     ○ MIXED / NO ALIGNMENT

---

# STEP 2 — CANONICAL TREND STATES

Each timeframe must resolve to exactly one state:

BULLISH
BEARISH

# STEP 3 — USE CLOSED BARS

The trend calculation must use CLOSED bars only.

Do not allow the current incomplete 4H or 15M candle to flip the official trend state unless the existing canonical system explicitly and safely supports intrabar state separately.

Display the timestamp of the last completed timeframe update.

Example:

4H BULLISH
updated 20:00 ET

15M BULLISH
updated 09:45 ET

# STEP 8 — UPDATE SPEED

15M state should update immediately when a new completed 15-minute bar becomes available.

4H state should update immediately when a new completed 4-hour bar becomes available.

The dashboard/status endpoint itself may poll more frequently.

Do not recalculate 4H trend from scratch every few seconds if nothing changed.

The operator should see the latest known state immediately.

# STEP 10 — EDGE LEDGER CONTEXT

This is important.

For every NEW ghost/Edge Ledger observation, preserve the trend context existing at signal time:

4h_trend_at_signal

15m_trend_at_signal

trend_alignment_at_signal

Do not modify historical rows.

Do not use these fields to qualify trades yet.

They are research metadata.

This lets us later compare:
