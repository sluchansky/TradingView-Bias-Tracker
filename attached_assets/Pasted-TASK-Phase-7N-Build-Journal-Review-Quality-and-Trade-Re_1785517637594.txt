TASK: Phase 7N — Build Journal Review Quality and Trade Review Workflow.

CONTEXT

The Journal foundation is now implemented with:

- Tradzella import
- server-side preview tokens
- duplicate detection
- confirm import
- rollback
- trade log
- trade detail
- analytics
- playbook
- display-only learning eligibility

The next goal is to make the Journal a real trade-review system rather than only a trade database.

PRIMARY GOAL

Create a structured review workflow for every closed trade.

The operator should be able to answer:

- What was the plan?
- What actually happened?
- Did I follow the plan?
- What mistake was made?
- What was done well?
- What should be repeated or avoided?
- Is this trade trustworthy enough for learning?

PART 2 — DEFINE REVIEW STATUS

Add one canonical review status.

Suggested states:

UNREVIEWED
IN_PROGRESS
REVIEWED
NEEDS_DATA
EXCLUDED

Define exact meanings.

Examples:

UNREVIEWED
Closed trade exists but no operator review has started.

IN_PROGRESS
Some review fields have been saved but review is incomplete.

REVIEWED
Required review fields are complete.

NEEDS_DATA
Execution, risk, or strategy identity is incomplete.

EXCLUDED
Trade intentionally excluded from analytics or learning with a reason.
