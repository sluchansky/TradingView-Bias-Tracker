TASK: DPv2 Analyst Briefing — Production Enablement and Narrative Summary

OBJECTIVE

Enable the existing DPv2 Analyst Briefing in production and add one concise
plain-English narrative summary generated only from the existing briefing fields.

IMPORTANT

The Analyst Briefing already is the narrative layer.

DO NOT create a second market-analysis engine.
DO NOT add indicators.
DO NOT recalculate market conditions.
DO NOT modify trading logic.
DO NOT modify broker or TradersPost behavior.
DO NOT connect the avatar during this phase.

PHASE 1 — ENABLE THE EXISTING FEATURE

Add the following environment variable to the production deployment:

DECISION_PIPELINE_V2_ENABLED=1

Requirements:

1. Do not alter the source-code default.
2. Keep default_on=False in code.
3. Enable the feature only through the production environment variable.
4. Preserve the ability to disable it immediately by changing the environment
   variable back to 0.
5. Do not remove password protection.
6. Republish the production deployment after the environment variable is set.

Before republishing, report:

- Current production revision
- Current value of DECISION_PIPELINE_V2_ENABLED
- Confirmation that the source default remains False
- Confirmation that the feature is display-only

After republishing, report:

- New production revision
- Boot-log confirmation that DECISION_PIPELINE_V2_ENABLED evaluated to True
- Confirmation that no broker, gateway, TradersPost, Discord, or order-routing
  settings changed

Do not claim to visually inspect the password-protected production dashboard.

PHASE 2 — ADD ONE CONCISE NARRATIVE SUMMARY

Extend the existing _dpv2_analyst_briefing() output with:

narrative_summary

This must be assembled only from the already-created briefing sections:

- Market Environment
- Primary Driver
- Money Flow
- Market Priority
- Technical Verdict
- Blocking Factors
- Next Action
- Invalidation

The summary must not read directly from raw alerts, indicators, global state,
broker state, or market feeds.

It must not call:

- full_analysis
- any strategy evaluator
- any scoring function
- any validation function
- any broker or gateway function
- any LLM or outside API

The summary must be deterministic template-based text.

EXAMPLE OUTPUT

Risk-Off conditions are being driven by geopolitical escalation. Gold is
showing the strongest relative flow while technology and broad equities remain
weak. MGC is currently the highest-priority market. The production engine
verdict is WAIT because VWAP and structure confirmation are still missing.
Next, watch for price to reclaim VWAP and confirm bullish structure. The idea
is invalidated by a sustained close below the active demand zone.

SUMMARY RULES

1. Maximum length: 90 words.
2. Use plain English.
3. Mention the production verdict explicitly.
4. Explain the leading market and why it is ranked first.
5. Include blocking factors only when they exist.
6. Include the next action.
7. Include invalidation only when defined.
8. Never invent missing information.
9. Use safe fallback language for unavailable fields.
10. Do not use prohibited execution terms:

- EXECUTE
- ROUTE
- ORDER
- SUBMIT
- FIRE

11. Do not include entry commands or trade instructions.
12. Set:

narrative_summary_source: "dpv2_existing_fields"
display_only: True

PHASE 3 — DASHBOARD PRESENTATION

Inside the existing ANALYST BRIEFING section, place the narrative summary at
the top.

Layout:

ANALYST BRIEFING

[Concise narrative summary paragraph]

Technical Verdict: WAIT
Source: Production Engine

[Existing 8 detailed sections below]

Requirements:

- Do not create another dashboard panel.
- Do not create eight new cards.
- Keep the existing detailed sections.
- Make the narrative paragraph the first thing the user reads.
- WAIT must remain amber.
- READY may be green.
- Blocking factors may be red.
- Normal explanatory text should remain neutral.
- Long text must wrap on mobile.
- No horizontal scrolling.
- The paragraph should not exceed approximately six lines on desktop.
