DASHBOARD REORGANIZATION — CLEANUP, UNIFIED MARKET BRAIN, AND HIGH-VOLUME SESSION VIEW

OBJECTIVE

Reorganize the existing dashboard before deployment and live testing.

Do not add another development phase.
Do not add new strategies, indicators, scoring models, AI services, or execution logic.

The goal is to:

1. Remove or repair blank panels.
2. Move approximately 75% of secondary panels into top navigation dropdowns.
3. Replace the current confusing Brain panel with one unified market interpretation.
4. Stop panels from displaying contradictory independent predictions.
5. Separate long-term context, intraday direction, and entry timing.
6. Add a dedicated High-Volume Session view for the three most important trading windows.
7. Preserve all existing trading, risk, webhook, TradersPost, thesis, and shadow-mode behavior.

This task is primarily dashboard architecture, data wiring, and presentation.

--------------------------------------------------
PART 1 — INVENTORY EVERY CURRENT PANEL
--------------------------------------------------

Before changing the dashboard, create a complete inventory of all existing panels.

For every panel, document:

- Panel name
- Frontend component/file
- Backend endpoint or data source
- Expected fields
- Fields actually received
- Polling or websocket method
- Whether data is current or stale
- Whether the panel renders correctly
- Whether the panel duplicates another panel
- Whether it issues an independent bullish/bearish verdict
- Recommendation:
  - KEEP ON OVERVIEW
  - MOVE TO MENU
  - FIX
  - REMOVE
  - ARCHIVE

Create a temporary developer report or markdown file containing this audit.

Do not remove a panel simply because it is currently blank until its endpoint and expected data have been checked.

--------------------------------------------------
PART 2 — HANDLE BLANK PANELS
--------------------------------------------------

For every blank panel, identify the exact reason.

Check for:

- Wrong API endpoint
- Old response schema
- Renamed fields
- Missing instrument normalization
- Frontend expecting camelCase while backend returns snake_case
- Feature flag disabled
- Backend not persisting data
- Polling never starting
- Failed websocket connection
- Silent JavaScript exception
- Empty database table
- Endpoint returning null
- Unsupported instrument
- Data being written to a different legacy table
- Market-closed state
- Component hidden behind incorrect conditions

Classify each blank panel as:

A. FIX
The feature is active and useful but the data connection is broken.

B. EMPTY BY DESIGN
There is currently no data, but the feature is valid.

C. OBSOLETE
The panel belongs to an old or replaced feature.

D. DUPLICATE
The same information is already displayed elsewhere.

Required behavior:

- FIX panels must be connected to the correct data.
- EMPTY BY DESIGN panels must display a clear empty state.
- OBSOLETE panels must be removed from the main dashboard.
- DUPLICATE panels must be consolidated.

Never leave a blank unexplained container.

Use messages such as:

- No thesis history recorded yet
- Waiting for first completed trade
- No active position
- No TradingView data received in the last 10 minutes
- Shadow validation has no completed outcomes yet
- Market is closed
- Feature disabled in environment settings
- Data source unavailable

Include:

- Last successful update
- Data source
- Error state when applicable

PART 5 — REPLACE THE CURRENT BRAIN PANEL
--------------------------------------------------

The current Brain panel is not useful enough and must be reorganized.

Do not make it a generic chatbot transcript.

The new Unified Market Brain must answer:

1. What is happening in the market now?
2. What is the higher-timeframe direction?
3. What is the intraday direction?
4. What is happening on the entry timeframe?
5. Are these layers aligned?
6. What does the bot expect price to attempt next?
7. What is the preferred trade scenario?
8. What is the alternative scenario?
9. What would invalidate the current interpretation?
10. Is the correct action ENTER, WAIT, MANAGE, or AVOID?

Required panel sections:

A. HIGHER-TIMEFRAME CONTEXT

Display:

- Direction: BULLISH / BEARISH / NEUTRAL
- Confidence
- Timeframes used
- Major structure
- Major supply/demand location
- Key higher-timeframe target
- Higher-timeframe invalidation

Suggested timeframes:

- Daily
- 4-hour
- 1-hour

B. INTRADAY CONTEXT

Display:

- Direction
- Confidence
- Current session trend
- 15-minute and 5-minute structure
- VWAP position
- Active intraday zone
- Session high and low
- Overnight high and low
- Previous-day high and low

C. ENTRY-TIMING CONTEXT

Display:

- 1-minute state
- 15-second or 5-second state when available
- Sweep status
- Delta/CVD status
- Micro structure
- Volume impulse
- Entry timing status:
  - CONFIRMED
  - FORMING
  - EARLY
  - LATE
  - NOT CONFIRMED

D. CURRENT MARKET PHASE

Use a controlled set of labels:

- TREND EXPANSION
- PULLBACK
- CONSOLIDATION
- BREAKOUT ATTEMPT
- FAILED BREAKOUT
- REVERSAL ATTEMPT
- LIQUIDITY SWEEP
- RANGE
- OPENING DRIVE
- CLOSING DRIVE
- LOW-LIQUIDITY CHOP

E. WHAT PRICE IS DOING

Generate one concise explanation from the actual evidence.

Example:

Price is pulling back inside a bullish intraday structure while holding above the session VWAP and testing an active demand zone.

F. EXPECTED NEXT PATH

Show:

Preferred path
Alternative path
Conditions required for each path
Key target levels

This is an interpretation, not a guaranteed forecast.

G. CURRENT ACTION

Use one final action:

- ENTER LONG
- ENTER SHORT
- WAIT
- MANAGE LONG
- MANAGE SHORT
- AVOID
- MARKET CLOSED

H. WAITING FOR

When action is WAIT, list the exact missing confirmations.

Example:

- 5-minute bullish CHOCH
- Reclaim of VWAP
- CVD flip bullish
- Volume above minimum threshold

I. INVALIDATION

Show:

- Invalidation level
- Invalidation reason
- Evidence that would make the thesis wrong

J. TRADE READINESS

Display:

- Higher-timeframe alignment
- Intraday alignment
- Entry-timing alignment
- Thesis status
- Confidence
- Edge score
- Shadow gate result
- Final readiness state

PART 6 — ONE SOURCE OF TRUTH FOR MARKET DIRECTION
--------------------------------------------------

Current panels must stop competing with each other.

Indicators and strategy modules may provide evidence, but they may not publish independent final trade directions on the main dashboard.

Required architecture:

RAW MARKET DATA
↓
EVIDENCE MODULES
↓
TIMEFRAME INTERPRETATIONS
↓
PERSISTENT MARKET THESIS
↓
UNIFIED MARKET BRAIN
↓
FINAL ACTION
↓
EXECUTION PATH

Examples of evidence modules:

- Market structure
- VWAP
- CVD
- Delta
- Volume
- RVOL
- Supply/demand
- Liquidity sweep
- Opening range
- Strategy matches

These modules may return states such as:

- bullish
- bearish
- aligned
- opposing
- confirmed
- weak
- unavailable

They should not independently display:

- BUY NOW
- SELL NOW
- EXPECTED UP
- EXPECTED DOWN

Only the Unified Market Brain should display the final interpretation and action.

Keep raw module details available in the MARKET menu.

PART 7 — MULTI-TIMEFRAME ALIGNMENT
--------------------------------------------------

Create one shared timeframe alignment object per instrument.

Suggested output:

{
  "instrument": "MNQ",
  "higherTimeframe": {
    "direction": "BULLISH",
    "confidence": 78,
    "timeframes": {
      "1D": "BULLISH",
      "4H": "BULLISH",
      "1H": "NEUTRAL"
    }
  },
  "intraday": {
    "direction": "BULLISH",
    "confidence": 71,
    "timeframes": {
      "15M": "BULLISH",
      "5M": "BULLISH"
    }
  },
  "entryTiming": {
    "direction": "BEARISH_PULLBACK",
    "confidence": 58,
    "timeframes": {
      "1M": "BEARISH",
      "15S": "NEUTRAL",
      "5S": "NO_SIGNAL"
    }
  },
  "combinedInterpretation": "Bullish context with a short-term pullback",
  "action": "WAIT",
  "waitingFor": [
    "5M bullish confirmation",
    "CVD bullish flip"
  ]
}

Create an Alignment Matrix in the brain panel:

4H     BULLISH
1H     BULLISH
15M    BULLISH
5M     NEUTRAL
1M     BEARISH PULLBACK
5S     NO SIGNAL

Then summarize it:

LONG-TERM: BULLISH
SHORT-TERM: PULLBACK
ENTRY TIMING: NOT READY
FINAL ACTION: WAIT

Do not label different-timeframe conditions as contradictions when they can coexist.

Examples:

- Bullish higher timeframe plus bearish 1-minute = bullish context with short-term pullback
- Bearish higher timeframe plus bullish 1-minute = bearish context with short-term bounce
- Mixed higher timeframes = neutral or transition
- Aligned higher and lower timeframes = directional continuation setup

SCALP mode:

- Higher timeframe provides context.
- 15M and 5M determine intraday direction.
- 1M, 15S, and 5S determine entry timing.

SWING mode:

- Daily, 4H, and 1H carry more weight.
- 15M and 5M are used for entry refinement.
- Micro timeframes must not reverse the swing thesis alone.

Do not create a second unrelated edge score.

--------------------------------------------------

Create a dedicated High-Volume Sessions view and a compact version on the Overview.

This panel should focus on the three highest-priority trading windows per instrument.

Initial configurable defaults:

MNQ / MES / MYM:

- Window 1: 9:30 AM–10:30 AM ET
- Window 2: 10:30 AM–11:30 AM ET
- Window 3: 3:00 PM–4:00 PM ET

MGC:

- Window 1: 8:20 AM–9:20 AM ET
- Window 2: 9:20 AM–10:20 AM ET
- Window 3: 1:30 PM–2:30 PM ET

Store these in configuration rather than hardcoding them throughout the UI.

Allow future configuration by instrument and mode.

The panel must have three operating states:

A. UPCOMING WINDOW

Show:

- Window name
- Start time
- Countdown
- Overnight high and low
- Previous-day high and low
- Session VWAP
- Important supply/demand zones
- Higher-timeframe bias
- Intraday bias
- Primary scenario
- Secondary scenario
- No-trade condition

B. ACTIVE WINDOW

Show:

- Time remaining

- Volume versus average
- RVOL
- VWAP state
- Sweep events
- Structure events
- CVD state
- Brain interpretation

C. COMPLETED WINDOW

--------------------------------------------------
PART 9 — BRAIN CONTROL DURING HIGH-VOLUME WINDOWS
--------------------------------------------------

The High-Volume Session panel should not be another isolated strategy.

It should change the presentation priorities of the Unified Market Brain.

Required behavior:

NORMAL MODE
- General thesis and market monitoring

WINDOW APPROACHING
- Build session plan
- Highlight key levels and scenarios

WINDOW ACTIVE
- Prioritize:
  - Opening range
  - Overnight high and low
  - Previous-day levels
  - VWAP
  - Volume expansion
  - RVOL
  - Liquidity sweeps
  - Break-and-hold
  - Sweep-and-reject
  - 5-minute structure
  - Fast-entry confirmation

WINDOW COMPLETE
- Grade the window
- Save the result
- Return to normal monitoring

Do not automatically submit a trade merely because a high-volume window begins.

All existing readiness, risk, and execution safeguards remain active.

PART 10 — DATA FRESHNESS
--------------------------------------------------

Every major dashboard data block must show freshness.

Required states:

- LIVE
- DELAYED
- STALE
- UNAVAILABLE
- MARKET CLOSED

Display:

- Last event timestamp
- Age of data
- Data source

Suggested stale thresholds must be configurable by data type.

Examples:

- Fast-entry data becomes stale quickly.
- Higher-timeframe structure can remain valid longer.
- VWAP data must not be presented as live if it was last refreshed 20 minutes ago.
- CVD must not display a current directional state if its latest alert is stale.

If critical data is stale, the brain must say so.

Example:

ACTION: WAIT
Reason: CVD and fast-entry data are stale.

Do not silently reuse old data as current confirmation.
