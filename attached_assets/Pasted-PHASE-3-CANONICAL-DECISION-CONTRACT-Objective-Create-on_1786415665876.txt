PHASE 3 — CANONICAL DECISION CONTRACT

Objective:

Create one authoritative, typed, auditable decision contract for the AI Trading Partner.

This phase is NOT a strategy rewrite and NOT an execution rewrite.

Do not change trading thresholds, strategy logic, risk limits, broker behavior, or live profitability behavior.

The goal is to eliminate ambiguous or duplicated meanings between:

- Main Brain
- Left Brain
- ORB
- strategy scanner
- manual entry
- auto-fire
- risk engine
- prop protection
- execution gateway
- Ghost Research Engine
- journal
- dashboard

Every live opportunity should have one canonical lifecycle.

3. STATE OWNERSHIP

Define exactly which layer owns each decision.

Example:

Strategy Engine:
OBSERVING → SETUP_FORMING → EARLY → READY

Qualification layer:
READY → QUALIFIED

Risk Engine:
QUALIFIED → RISK_PENDING → RISK_APPROVED

Execution safety:
RISK_APPROVED → EXECUTABLE

Execution Gateway:
EXECUTABLE → ENTRY_REQUESTED → ORDER_ACCEPTED / ORDER_REJECTED

Position manager:
ORDER_ACCEPTED → POSITION_ACTIVE → MANAGING → COMPLETED

No other module may arbitrarily skip states unless explicitly documented.

4. WAIT IS NOT A FAILURE

Clarify WAIT semantics.

WAIT should mean:

No executable setup currently exists.

WAIT is not equivalent to:

DATA ERROR
BLOCKED RISK
BLOCKED PROP
BLOCKED SAFETY
EXPIRED

Those must be separate canonical states/reasons.

5. EARLY MUST NEVER LIVE FIRE

Enforce the semantic contract:

EARLY = research/advisory only.

EARLY must never become EXECUTABLE directly.

If any current code allows EARLY half-size live execution, identify it and place it behind a legacy compatibility flag.

Do NOT change behavior yet without explicit migration approval.

Report the exact legacy path.

6. READY VS QUALIFIED

Define:

READY =
Strategy conditions are satisfied.

QUALIFIED =
READY plus all non-risk market/strategy qualification gates have passed.

This distinction must be explicit.

A READY trade can still fail qualification.

7. RISK APPROVAL IS SEPARATE

Risk approval must never be implied by READY.

The contract must distinguish:

READY
QUALIFIED
RISK_APPROVED
EXECUTABLE

A trade is not sendable until all four required stages have been passed.

8. MANUAL TRADING

Manual Trade Desk LONG/SHORT may bypass strategy qualification if that is current intended behavior.

However it must still enter the canonical contract at an explicit state such as:

MANUAL_REQUESTED
or
QUALIFIED_MANUAL_OVERRIDE

It must still pass:

risk
daily loss
prop protection
duplicate guard
execution mode
safety lock
broker validation

Do not let manual trading exist outside the canonical decision trail.

9. AUTO-FIRE

Auto-fire must consume canonical decisions.

It must not independently infer READY from raw fields.

Required chain:

decision.state == EXECUTABLE
AND execution enabled
AND arm valid
AND safety valid
→ gateway request

No duplicate interpretation of strategy rules inside auto-fire.

10. ORB MAPPING

Map all ORB states into the canonical contract.

Do NOT delete OrbEngine's internal state machine if it is useful.

Instead define an explicit mapping.

Example:

WATCHING_BREAKOUT → SETUP_FORMING
BREAKOUT_DETECTED → EARLY or READY depending confirmation
CONFIRMATION_PENDING → EARLY
QUALIFIED → QUALIFIED
BLOCKED_BY_MAXIMUM_CHASE → BLOCKED_CONFIRMATION / MARKET
ENTRY_REQUESTED → ENTRY_REQUESTED
ORDER_ACCEPTED → ORDER_ACCEPTED
POSITION_ACTIVE → POSITION_ACTIVE
COMPLETED → COMPLETED

Document every mapping.

13. TRANSITION VALIDATION

Implement legal-transition checking.

Examples:

READY → ORDER_ACCEPTED
must be illegal.

RISK_APPROVED → EXECUTABLE
legal.

EXECUTABLE → ENTRY_REQUESTED
legal.

ORDER_ACCEPTED → POSITION_ACTIVE
legal.

COMPLETED → READY
illegal for the same decision_id.

Invalid transitions should:

- log clearly
- not crash live trading
- fail closed for new broker transmission
- preserve the previous valid state
