PART 2 — DEFINE MANAGEMENT EVENT CONTRACT
==================================================

Use one canonical event shape:

{
  "event_id": "...",
  "timestamp": "...",
  "event_type": "STOP_MOVED",
  "instrument": "MNQ",
  "internal_trade_id": "...",
  "old_value": {...},
  "new_value": {...},
  "price": 24175.25,
  "quantity": 1,
  "source": "SYSTEM_AUTO",
  "reason_code": "BREAK_EVEN_TRIGGERED",
  "reason": "TP1 reached; stop moved to entry",
  "automated": true,
  "operator_id": null,
  "broker_event_id": null,
  "metadata": {}
}

Required properties:

- deterministic event ID when possible
- UTC timestamp
- explicit event type
- explicit source
- explicit automated/manual flag
- structured reason code
- safe metadata
- no credentials or authorization data

Do not store raw broker responses without sanitization.

PART 5 — WIRE ACTIVE-TRADE EVENTS
==================================================

Instrument the existing management code paths without changing their decisions.

Required linkage:

- lifecycle → ACTIVE
- append POSITION_OPENED
- actual entry and quantity merged into execution

STOP PLACED

- append STOP_PLACED

TARGET PLACED

- append TARGET_PLACED

STOP MOVED

- append STOP_MOVED with old and new stop

BREAK EVEN

- append BREAK_EVEN_MOVE
- identify trigger when available

TRAILING STOP

- append TRAILING_STOP_UPDATE

PARTIAL OR TARGET HIT

- append TARGET_HIT

MANUAL EXIT

- append MANUAL_EXIT
- include operator reason when available

EMERGENCY FLATTEN

- append EMERGENCY_FLATTEN
- preserve exact emergency reason

FINAL CLOSE

- append POSITION_CLOSED
- lifecycle → CLOSED
- compute and persist final outcome

Do not alter stop or target logic to make journal capture easier.

PART 6 — DETERMINISTIC TRADE LINKAGE
==================================================

Use this priority:

1. internal_trade_id already present on active-trade record
2. broker or TradersPost order ID
3. execution fingerprint
4. signal ID
5. existing deterministic active-trade linkage

Do not match only by instrument when multiple same-instrument trades could exist.

The existing `_nj_find_open_by_instrument` helper may only be used where the system guarantees one open trade per instrument.

Document that invariant and add tests.

If that invariant is not guaranteed, replace instrument-only lookup with deterministic identity before instrumenting the path.
