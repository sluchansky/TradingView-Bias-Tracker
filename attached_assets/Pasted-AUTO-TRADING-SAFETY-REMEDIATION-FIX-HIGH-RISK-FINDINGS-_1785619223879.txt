AUTO-TRADING SAFETY REMEDIATION — FIX HIGH-RISK FINDINGS ONLY

Do not add strategies, change scoring formulas, loosen gates, redesign the UI, or refactor unrelated code.

Keep execution in paper mode throughout this task.

Do not transmit any live TradersPost orders.

Goal

Resolve the three HIGH findings from AUTO_TRADING_SYSTEM_AUDIT.md:

1. Missing EXECUTION_MODE can default to live TradersPost
2. Databento connectivity is not a hard pre-execution gate
3. Learning Rule Engine exceptions fail open

Also fix the directly related candidate-freshness and blocked-attempt audit gaps.

If it is anything else, stop outbound execution immediately by setting the effective mode to paper or disabled before continuing.

2. Fix execution-mode resolution

Find resolve_execution_mode() and every other place that resolves or infers execution mode.

Change the rules to:

* Missing EXECUTION_MODE → disabled
* Blank EXECUTION_MODE → disabled
* Invalid value → disabled
* paper → paper only
* disabled → no execution
* traderspost → live routing only when explicitly configured
* A configured webhook must never enable live execution by itself
* Legacy variables must not override an explicit disabled or paper value
* Mode comparisons must be case-insensitive
* Backend status must expose both configured mode and effective mode
* The frontend must display the backend effective mode rather than infer it

Required invariant:

No explicit live authorization = no outbound order

Add tests for:

* Missing mode
* Blank mode
* Invalid mode
* Mixed-case values
* Explicit paper
* Explicit disabled
* Explicit traderspost
* Webhook present with missing mode
* Webhook present with disabled mode
* Conflicting legacy/current settings
* Restart or config reload

Every non-explicit-live case must assert that the outbound transport was not called.

3. Add a mandatory Databento health gate

Add a hard backend gate immediately before candidate claiming and again immediately before transmission.

The gate must verify:

* Databento is enabled
* Connection state is healthy
* The requested instrument is subscribed
* Latest canonical tick is fresh
* Latest completed bar is fresh
* VWAP is fresh
* Candidate is fresh
* Market state is not empty
* No required timestamp is missing or malformed
* No timestamp is materially in the future
* Freshness data belongs to the same instrument
* The system is not treating a maintenance halt or closed market as tradable
* Unknown health state blocks execution

Define freshness thresholds centrally.

Do not use the existing 30-minute VWAP window as sufficient approval for intraday execution.

Use strategy/timeframe-aware thresholds where practical. If the current architecture cannot support that cleanly, use conservative centralized thresholds and document them.

Required invariant:

Disconnected, stale, missing, conflicting, or invalid market data = NO TRADE

Add tests for:

* Healthy feed
* Disconnected feed
* Unknown connection state
* Databento disabled
* Unsubscribed instrument
* Stale tick
* Stale completed bar
* Stale VWAP
* Stale candidate
* Missing timestamp
* Malformed timestamp
* Future timestamp
* Wrong-instrument timestamp
* Empty market state
* Maintenance halt
* Feed disconnect after initial approval but before transmission
* Reconnect before fresh data arrives

For every blocked case, assert zero outbound webhook calls.

4. Fix Learning Rule Engine exception handling

Audit both Learning Rule Engine checks in the execution path.

Represent these states explicitly:

* pass
* block
* disabled
* insufficient samples
* no optional learning data
* exception
* timeout
* malformed result
* contradictory result
* strategy-key mismatch

Safe behavior:

* Disabled → no influence
* Insufficient samples → no influence
* Missing optional learning data → no influence
* Explicit block → block execution
* Exception → block auto-execution
* Timeout → block auto-execution
* Malformed result → block auto-execution
* Contradictory result → block auto-execution
* Strategy-key mismatch → block auto-execution

Do not treat engine failure as equivalent to “no learning influence.”

Add structured diagnostics with:

* State
* Strategy key
* Rule key
* Sample count when available
* Exception class
* Whether execution was blocked
* Error counter

Do not log secrets or full stack traces containing credentials.

Required invariant:

A safety-engine error can never become approval

Add tests at both LRE checkpoints for every state above.

5. Enforce final candidate freshness

Validate the final execution candidate’s:

* Candidate ID
* Creation timestamp
* Market-data timestamp
* Strategy-evaluation timestamp
* Expiration timestamp, if present
* Market-state generation or cycle ID, if present

Block when:

* Timestamp is absent
* Timestamp is malformed
* Candidate is too old
* Timestamp is materially in the future
* Candidate belongs to an older market-state cycle
* Setup was invalidated after candidate creation
* Candidate instrument differs from execution instrument

Include the candidate timestamp or generation ID in the deterministic idempotency key.
