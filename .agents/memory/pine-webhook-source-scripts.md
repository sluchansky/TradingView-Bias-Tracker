# Pine webhook source scripts

The webhook alerts are produced by repo-owned Pine v5 indicators the user pastes
into TradingView, in `artifacts/tradingview-webhook/pine/`:
`{confirmation_candle,liquidity_sweep,volume_spike}.pine` (prefixed per-instrument),
plus `market_structure.pine` (BOS/CHOCH) and `cvd_bias.pine` (CVD).
Zones still come from the user's own SMC indicator (no repo zone script).

**Prefixed vs shared:** confirmation/sweep/volume/CVD/zones are PER-INSTRUMENT
prefixed ("MES BULLISH SWEEP"); structure (BOS/CHOCH SUPPLY/DEMAND) and HH/HL/LH/LL
are SHARED/un-prefixed and routed by the `ticker` field. Prefixing a structure
alert ("MES BOS DEMAND") makes it UNRECOGNIZED — emit bare "BOS DEMAND" + ticker.
Each builds the exact JSON the app expects (real `syminfo.ticker` + `str.tostring(close)`,
fired via `alert(..., freq_once_per_bar_close)`; the TV alert condition must be
"Any alert() function call", NOT a plot-crossover). Hand-typed alerts with
`{{ticker}}`/`{{close}}` placeholders do NOT work — TV doesn't substitute them inside
an `alert()` message, so the app rejects the literal text.

**Rule:** Adding a new instrument end-to-end takes TWO edits, not one — the app's
instrument registry (`_ALERT_INSTRUMENTS` + resolver + VWAP/vol feed map in app.py)
AND the instrument auto-detect in each Pine script.

**Why:** Each script derives its alert prefix from the symbol with a fallback that
defaults ANY unrecognized ticker to `"MGC"` (e.g. `str.contains(ticker,"MNQ")?"MNQ":"MGC"`).
So an instrument added only app-side gets ZERO matching webhooks (or worse, a script
on its chart silently emits the wrong prefix, e.g. MGC payloads on an MES1! chart).

**How to apply:** When supporting a new contract, extend the nested-ternary symbol
detection AND the `manualPrefix` dropdown options in all three Pine files. The four
supported roots (MGC/MNQ/MES/MYM) have no substring collisions; keep MGC as the
final fallback. No app.py change is needed if the registry already lists it.
